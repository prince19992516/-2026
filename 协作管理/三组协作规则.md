# A、B、C组职责：AI辅助，人工验证与判断

> 核心原则：AI可以生成内容、提出候选推导和辅助分析；学生必须实际核验、运行、解释并对最终结论负责。三组都可以使用AI，使用范围和证据要求不同。

本规则按当前教学安排采用固定A/B/C三组，八章均需三组参与；组内按章节安排负责人。C组不再被规定为“所有推导和代码都必须完全不用AI”。人工完成的部分与AI辅助的部分必须分别标明，不能把AI输出改写后声明为独立手算或手写代码。

## 1. 分工总览

| 组别 | 核心问题 | AI可以辅助 | 必须由学生完成 | 每章主要产出 |
| --- | --- | --- | --- | --- |
| A组：主笔 | 怎样把这一章写清楚、做成可运行教材？ | 文献线索、初稿、候选推导、代码、例题习题、润色 | 核对来源与公式条件；核验关键推导；运行全部代码；加入自己的解释与例子；组织教学内容 | 正文、实验Notebook、习题与解答、编写报告 |
| B组：验证 | 在约定条件下，这些推导和实验能否独立复现？ | 对比推导、测试思路、调试、报告结构 | 先独立建立预期；复核关键推导；在干净环境实际运行；比较误差；判断问题并写修正清单 | B组独立推导、验证Notebook、验证报告、修正清单 |
| C组：批判 | A与B共同漏掉了什么？结论在哪些条件下失效？ | 漏洞线索、候选反例、方法对比、验证代码草稿、报告结构 | 核实漏洞与反例；人工阅读对比来源；解释关键计算；记录真实AI原话；判断影响并提出改进 | 人工复核Notebook、必要的手动推导、批判报告、AI陷阱集 |

三组均维护AI对话记录。报告可以由AI辅助整理表达，但事实、证据、优先级和最终结论由组员填写并签认。

## 2. A组：主笔与修订

### AI可以做什么
提供文献检索线索、生成正文与推导草稿、实验代码、例题和习题，辅助润色。AI给出的题名、作者、公式和运行结果都先视为待核查内容；没有实际检索能力的模型所列文献不能当作已找到原文。

### 学生必须做什么
1. 所有公式核对符号、维度、定义域和假设；关键推导逐步手算或人工解释。其余引用结果标明可靠来源及使用条件，不要求机械地重证所有已引用定理。
2. 实际运行每个代码单元，用解析解、独立方法或高精度基准核对结果；运行不报错只是起点。
3. 检查每道习题与参考解答，加入至少一个本组设计或实质改编的例子，并说明改动目的；不要只替换AI例子里的数字。
4. 人工打开文献原文或可信版本，记录具体页码/章节；不以另一个AI再次确认作为引用证据。
5. 用自己的话解释算法、结果与局限，统一符号和章节结构；记录AI建议中采纳、拒绝及修订的内容。

### 工作流与交付
列学习目标 → AI辅助初稿 → 人工核验公式与来源 → 运行代码与习题 → 加入本组解释/例子 → 提交编写报告及固定版本 → 回应B/C问题并修订。

交付：`正文.md`、`实验.ipynb`、`习题.md`、`习题参考解答.md`、`编写报告.md`、`AI对话记录.md`中的A组部分。A组对最终正文与实现的修改负责，B/C不要直接覆盖A的成果代替问题记录。

## 3. B组：独立验证与复现

### “独立”具体指什么
先只看助教给出的题目、假设、参考资料和验收指标，不看A的推导、代码与AI对话。组员先写下关键推导、预期结果和测试方案，保存版本或时间记录，再用另一AI生成对比思路；明确标出AI补充了哪一步。完成这份初始记录后，再打开固定的A组版本进行对照。

关键结论需要一份组员能够独立讲清的人工推导或可信基准，不能把AI给出的另一段推导直接称为“本组独立手算”。与A意见一致也必须有证据。

B组应使用与A不同的AI工具或模型，并登记名称、版本和日期。若受账号/经费限制只能使用相同模型，明确记录限制，由助教事先确认替代方案（如增加人工参考算法和原始文献核验），不得隐瞒为已满足“另一AI”要求。不同模型本身不保证独立正确。

### 学生必须做什么
1. 在一份新的课程副本中新建虚拟环境，只安装仓库声明的依赖；固定A的完整commit并从干净内核运行。**仅重启内核不等于重新验证安装环境。** [干净环境复现步骤](../教程/07-B组如何在干净环境复现.md)无需先学Docker。
2. 检查主要结论的正确性、数值误差、维度、单位，以及与本章有关的正常、边界和极端输入。没有定义的输入应检查是否有明确限制，而不是要求算法支持一切输入。
3. 对适用的算法做网格/步长收敛、守恒量或独立求解器对照。测试预期与容差先给依据，不能先看A输出再把它抄成参考值。
4. 记录实际环境、命令、种子、设备、输出差异和失败信息；AI可以调试，但“已经运行”必须来自真实执行。
5. 输出问题清单，并在A修复后记录复测版本和结果。

交付：`B组独立推导.md`、`验证.ipynb`、`验证报告.md`、`修正清单.md`及AI记录。B主责常规正确性与复现，不要求复制整章写作工作。

## 4. C组：批判、边界审查与AI陷阱

### AI可以做什么
建议检查隐含假设、给出候选反例、提出替代方法、生成验证代码草稿，协助查找和整理其他教材的表述。C组可借助这些建议缩小检查范围，但不能把AI的“可能有问题”直接写成已确认错误。

### 学生必须做什么
1. 优先检查会改变结论的遗漏：边界条件、稳定性假设、误差界适用域、病态与算法稳定性的混淆、数据泄漏、不公平比较等；语言润色意见单独列为编辑建议。
2. 对每条候选漏洞给出手算、来源或实际运行证据。验证代码可由AI辅助，但组员必须解释关键计算、核对参考值、实际运行，并标出代码来源和人工修改。
3. 在 `手动推导.md` 保存所审关键问题的人工验证步骤。可记录AI启发，但不能复制候选推导当作独立手算；不要求重做全章所有证明。
4. 对AI陷阱保留提示词、回复原文、模型和日期；能公开的截图/对话导出可作附件，但需附可检索文字并删除敏感信息。人工构造的错误例子必须标为“教学构造”，不能伪造AI曾经说过。
5. 至少选一种相关教材处理方式或基准方法进行人工核对，在批判报告说明假设、误差、稳定性与成本中适用的比较维度；复杂章节可按助教约定缩小范围。
6. 检查A的主张与B的验证是否共同依赖同一个错误前提，提出具体教材改法，并复核修复是否奏效。

交付：`手动推导.md`、`人工复核.ipynb`、`批判报告.md`、`AI陷阱.md`及AI记录。文件名“人工复核”指人工承担验证责任，不表示全部代码都禁止AI辅助。

## 5. AI陷阱怎样记录才算证据

| 环节 | C组要保留的内容 |
| --- | --- |
| 候选线索 | 来源、提示词、AI原话或人工构造说明 |
| 人工验证 | 假设、推导/可信来源、最小输入、参考值与容差、实际输出 |
| 判断 | 已确认错误 / 不成立 / 条件不足暂不能判断；说明理由 |
| 影响 | 影响哪个结论或实验，严重程度与范围 |
| 修复 | 正确表述或代码修改建议、责任人、修复commit |
| 复测 | 修复后的运行证据与剩余局限 |

不要要求每章必须找出固定数量的AI错误。未发现问题时，提交查验范围、方法与局限；被证明不成立的候选反例也可保留，它体现核验过程，不应计为“已发现陷阱”。助教的自动脚本只检查记录结构。

## 6. 修正容易混淆的提示词

“请给出条件数大但良态的反例”容易把定义混在一起。在同一问题定义、输入输出尺度和范数下，大条件数通常正是病态的表征。可以把这句话作为辨析题，但不能预先要求AI一定生成符合它的真实反例。

更合适的问题是：“构造一个病态线性系统，说明某次特定右端或扰动方向的求解误差仍可能很小；区分问题的条件数、算法稳定性、残差和解误差。”

类似地，询问float32精度时须区分有效二进制位数、约能表示的十进制有效数字、机器epsilon和具体计算误差；先定义问题，再判断AI回答是否错误。比较教材时应查原文，不能凭AI对作者观点的概括给教材定错。

## 7. 一章的协作闭环
1. 助教给出范围、关键主张、负责人和日期。B从独立题目开始准备基准，A准备初稿，C整理风险清单；不必让所有工作串行等待。
2. A提交自检后的固定版本与编写报告。
3. B保存先验推导后对照A并在新环境复现；C可同步审查A，待B报告提交后再检查A/B共同遗漏。
4. 问题按 `CH01-B001`（验证问题）、`CH01-C001`（批判问题）编号；陷阱条目用 `CH01-T001` 并与问题互相引用，避免重复算问题。
5. A集中修订；B复测数值和复现问题，C复核假设、反例与表述。分歧由证据和助教裁定，不以AI投票定论。
6. 助教检查最终内容、三组报告、阻断问题关闭、引用与HTML构建，再更新章节状态。

报告记录“被审的内容commit”，修复和复测另列新commit。报告文件自身的版本由Git追踪，不要求在报告里写入它自己尚未产生的commit。

## 8. 时间与评价

以下是**每位学生每周课外投入的参考预算**，不是每章都额外增加这些工时；具体任务按成员和章节难度分配，先由导师确认。

| 组别 | AI交互与整理 | 人工推导、运行、核验与写作 | 合计 |
| --- | --- | --- | --- |
| A | 约2小时 | 约3小时 | 约5小时 |
| B | 约1小时 | 约3小时 | 约4小时 |
| C | 约1.5小时 | 约2.5小时 | 约4小时 |

设计上让人工投入多于AI交互。周报按实际工作填写，不为凑比例编造时间；程序后台运行和下载等待不计为独立推导工时。长时间训练应由助教另定计算预算，不能变成无上限的学生投入。

评价重点是内容质量、验证覆盖、证据可信度、可解释性和修订闭环，不按AI对话长度、报错数量或陷阱数量排名。每周每组交周报、每章每组交报告、期末每组交综合报告，并注明个人贡献。

## 9. 最终验收
正文与习题覆盖约定目标；A已人工自检；B有独立预期和干净环境复现；C有经过核验的风险分析与方法比较；三组披露AI使用；阻断错误已修复复测；来源可核查；完整教材构建成功。CI绿色、另一AI认可或“没有发现问题”都不能单独代替验收。
