## 四、注意点（请先看这一节）

### 4.1 GitHub 上后半段公式显示“Unable to render expression.”——不是文件坏了

正文有 **1,853 个公式**，GitHub 的数学渲染器按“每个公式内容中 `{` 的个数 + 1”计渲染单元，**整页累计超过 2,000** 后，从越线公式起后面全部显示 `Unable to render expression.`。本章实测：

| 小节 | 公式数 | 本节单元 | 累计单元 | 状态 |
| --- | ---: | ---: | ---: | --- |
| 3.1 | 352 | 609 | 609 | 正常 |
| 3.2 | 415 | 686 | 1,295 | 正常 |
| 3.3 | 727 | 1,026 | **2,321** | 约在 3.3.5 越线 |
| 3.4 | 359 | 525 | **2,846** | 全部不显示 |

- **根因**：GitHub 前端渲染预算，不是 Markdown/LaTeX 语法错误；同一份文件在 KaTeX 0.16 下 1,853 个公式全部通过。
- **本地看**：VSCode 打开正文，`Ctrl+Shift+V` 预览即可；`settings.json` 确认：
  ```json
  "markdown.math.enabled": true,
  "markdown.preview.breaks": false
  ```
- **GitHub 看**：可点 `Raw` 下载后用 VSCode 看；若必须在线评审，可临时按节拆一份“评审副本”（提交的完整正文不要删公式、不要换成图片）。
- **不要为了过 GitHub 而删公式或改写法**；这会把可核对的内容改坏。

### 4.2 习题与解答的公式写法

习题/解答为了在 GitHub 上尽量可读，行内公式用了“美元符号 + 反引号”的包裹形式，独立公式用 math 围栏。**VSCode 内置预览不认这两种写法**（会显示成代码），要看请用 “Markdown Preview Enhanced” 扩展，或直接看正文（正文是标准 `$...$` / `$$...$$`）。

### 4.3 图片路径
