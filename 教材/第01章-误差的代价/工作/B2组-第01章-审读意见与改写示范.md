## 2. 读者视角：钩子为什么会被浪费

### R1 开篇 10 行内，钩子被四段论述淹掉

A1 第 5–34 行的开场是**全书最好的一段素材**：`sqrt(x+1)-sqrt(x)` 在 $x=10^{16}$ 时给出 0，换等价公式给出 $5\times10^{-9}$，还附了真实的 REPL 记录。这是一个能让人当场愣住的现象。

但紧接着第 36、38、40、53 行是四段连续论述：先讲“需要了解计算机怎样表示数”，再讲“核心问题是凭什么相信”，再讲误差来源分类，最后讲先修知识与课时安排。**读者刚被勾起的好奇，被四段“课程介绍”按住了。**

> 判断依据：吸引力有三个来源——意外、具体、可回答。第 5–34 行三个都占；第 36–53 行一个都不占。

### R2 全章没有一次“让读者先猜”

A2 第 15 行有一句 A1 没有的话：

> **先猜，再验证：** 对 $x=10^{16}$，直接计算 …与计算 …，会得到相同结果吗？先预测，再运行本章实验。

这是**把读者从观众变成参与者**的一句话，成本几乎为零。A1 全文 24 个问句里，没有一句是“先猜”式的——问句都在解释里，不在读者身上。

### R3 90 KB 的正文，一个列表都没有

A1 有 375 段、平均 92 字、最长 558 字；全文**无序列表 0 项、有序列表 0 项**。这意味着读者面对的是连续 375 个段落，中途没有任何视觉停点。

> 判断依据：长文阅读的疲劳来自“不知道还有多久”。列表、表格、加粗结论、图，都是告诉读者“这一段结束了”的路标。A1 有 3 张图和若干表，但密度不足以支撑 90 KB。

### R4 “选读”标注出现得太晚

A1 在正文中段才出现“选读”标签，而第 53 行讲课时安排时只说“标为‘选读’的推导与附录供进一步学习”。读者读到第 900 行才知道“原来前面那些可以不看”。

**改法：** 把阅读路线放到开篇，让读者在第 30 秒就知道“我最低限度要读哪几段”。

### 4.1 开篇（替换 A1 第 1–53 行）

```markdown
# 第01章　误差的代价

## 一个 0 引发的怀疑

先花十秒做一个实验。打开 Python，输入这两行：

>>> import math
>>> x = 1e16
>>> math.sqrt(x + 1) - math.sqrt(x)
0.0
>>> 1 / (math.sqrt(x + 1) + math.sqrt(x))
5e-09

同一个数学量 $\sqrt{x+1}-\sqrt{x}$，在 $x=10^{16}$ 时，第一种算法给出 **0**，第二种给出 **5×10⁻⁹**。

第一种答案不是"算错了"——计算机忠实地执行了它被要求执行的运算。它只是**没有足够的有效位**来表示那个差额。而第二种答案也不是"更聪明"——它只是把同一个数写成了一种不会把差额弄丢的形式。

这里藏着三个问题，本章逐一回答：

1. **为什么 1 会在 $10^{16}$ 旁边消失？**
   因为那里相邻两个浮点数的间距是 2.0，加 1 还不到半个间距。（1.1 节）
2. **为什么换一个等价公式就救回来了？**
   因为两个公式的误差不同，而误差会在减法中放大。（1.2 节）
3. **为什么这个问题今天还在决定模型能不能训练？**
   因为 Softmax、交叉熵和梯度累加都在做同一类运算。（1.3、1.4 节）

## 误差是价格，不是错误

计算从来不是免费的。想更准，就要付三样东西之一：更多的位数、更巧的公式、更长的时间。

本章不打算让你记住"误差有几种"，而是让你在三个具体场合能做出判断：

| 场合 | 你要回答的问题 | 在哪一节 |
| --- | --- | --- |

| 步长 $h$ 取多少 | 为什么再小反而变差？ | 1.2 |
| 换一个算法 | 是问题本身敏感，还是算法不稳？ | 1.3 |
| 训练损失变成 NaN | 该改公式还是改精度？ | 1.4 |

## 三条阅读路线

- **最短路线（约 2 小时）**：读每节开头的场景、结论表和"自检"三行，跳过所有标"选读"的段落。
```

### 4.2 1.1 入口（替换 A1 第 55–91 行）

```markdown
## 1.1　浮点数与舍入误差（2学时）

### 先看一个几乎所有人都会愣一下的结果

>>> 0.1 + 0.2
0.30000000000000004
>>> 0.1 + 0.2 == 0.3
False

误差是 $5.551\times10^{-17}$。它小到肉眼看不见，却足以让一个等号变成 `False`。

这一节回答三个问题：这个 $10^{-17}$ 从哪来？为什么它不能更大、也不会更小？什么时候可以放心忽略它？

### 计算机存不下 0.1

用一句话说：**十进制的小数，大多不是二进制的有限小数。**

$0.15625$ 是，因为 $0.15625=1/8+1/32$；$0.1$ 不是，因为 $0.1=1/10$，分母里有因子 5，而二进制只认 2 的幂。所以 $0.1$ 在 `float64` 里存的是一个离 $0.1$ 最近的、能用 53 位二进制表示的数。

### 正式一点：机器数的形状

一个非零的规格化二进制浮点数写成

$$
x=(-1)^s(1.b_1b_2\cdots b_{p-1})_2\,2^e .\tag{1.3}
$$

$s$ 定符号，$e$ 定数量级，$p$ 位有效数定这个数量级上的分辨率。`float64` 的 52 个显式小数位加上隐含首位，得到 $p=53$ 位有效二进制精度——所以它是"约 16 位十进制有效数字"，而不是"64 位有效数字"。

### 由此得到间距，再由间距得到那个 0

固定指数区间 $[2^e,2^{e+1})$ 内，相邻规格化数的间距是

$$
\Delta_e=2^{e-p+1}.\tag{1.4}
$$

指数每加 1，间距翻倍。这就是浮点数"近处密、远处疏"的来源，也是开篇那个 0 的答案：

>>> math.ulp(1e16)
2.0
>>> (1e16 + 1) == 1e16
True

$10^{16}$ 附近的间距是 2.0，加 1 不到半个间距，舍入后回到原处。

> **停一下。** 到这里你应该能回答开篇的问题 1 了。如果不能，回到式(1.4)代入 $e=53$ 算一遍 $\Delta_e$。
```
