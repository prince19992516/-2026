## 三、A1（G14）核查结论

### 3.1 先说做得好的

在列问题之前，先把**该夸的夸到位**——这些也是本组复现时最省力的地方：

1. **4.1 的推导是"能自己走通"的那种。** 从消元矩阵 $E_k=I-v_ke_k^T$ 推出 $L=I+\sum_k v_ke_k^T$，再单独用分块证明"换行时只交换 $L$ 已完成的列"。本组照这个思路独立实现，一步没错。
2. **两种很专业的自检。** 故意漏换 $L$ 乘子、看 $PA-LU$ 误差变成 0.5；非正定、非对称、奇异输入必须抛异常。这两招本组也常用。
3. **用 `Fraction` 区分"输入舍入"与"算法误差"**，本组直接沿用，并在 I.2 里接着往前推了一步。
4. **4.3 的八个推导是真证明**，而且每条末尾都有"条件不满足时会怎样"。
5. **4.4 的分寸感**：明确写"PyTorch 未安装、自动微分未验证"，反复强调"LoRA 不是对 $W_0$ 做截断 SVD"——不硬凑结论。

## 四、A2（G18）核查结论

### 4.1 先说做得好的

同样先夸。这份稿子的**实验设计**是两组里最讲究的：

1. **4.2 用 $A=\operatorname{diag}(d)\,T\,\operatorname{diag}(d)$ 把机制讲透了。** 对角尺度差异是条件数的主因；再配常数对角的控制实验，"预条件不是加了就有效"这句话就有了实证。本组复现时，预条件后条件数 $4.99644$ 与解析式 $(3+2\cos\frac{\pi}{n+1})/(3-2\cos\frac{\pi}{n+1})$ 逐位相符。
2. **覆盖最全。** 追赶法、$LDL^T$、线性定常迭代（谱半径判据）、Jacobi/Gauss-Seidel 都有，4.1.4 的追赶法稳定性归纳证明还是完整的。
3. **4.4 有一条完整的链。** 岭回归闭式解 → 协方差特征分解 → LoRA 低秩增量 → CG + 隐函数定理反传，四步串得清楚，另一份稿子没有这条线。
4. **随堂提问的答案比正文还严谨。** 第 2577 行的回答已经把"能量集中在 $C$ 的主方向、不是 $\Delta W$ 的奇异方向"说对了，说明作者其实清楚条件，只是正文那几句写漏了。
5. **工程习惯好。** 锚点与编号规范、`expect_error` 检查异常输入、SciPy 交叉对照、$128\times128$ 规模核验，都比模板要求更细。

问题集中在**四处"由结构直接推结论"**（4.1.3、4.1.2、4.4.2、4.4.4），其余都是小修。

### 4.3 总体判断

G18 的 4.2 是两份稿子里实验设计最好的部分：$A=\operatorname{diag}(d)T\operatorname{diag}(d)$ 让"对角尺度是条件数主因"这件事成为可验证的机制，还配了常数对角的控制实验，把"预条件不是加了就有效"讲清楚了。4.1 的追赶法、$LDL^T$ 与 4.4 的完整连接也比另一份稿子覆盖得多。

问题集中在 **4.1.3 的推理起点**和 **4.4.4 的三条因果链**——它们都是"由结构直接推出结论"的写法，一旦条件缺失就会给出错误结论，而且**用本组自己的实验就能反驳**（$\Delta W^*=(0,99.99)$ 就是最直接的反例）。这类问题文字修改量不大，但必须改：它们是整章 4.4 的理论落点，被整合组直接采用的风险最高。

另外两处是工程性的：Notebook 里 `A_q3` 被定义两次且取值不同（G18-12），以及计时表与保存输出不一致（G18-10）。

## 九、结论与局限

**结论**

1. **数值层面，两份稿子都可以复现。** 4.1、4.3、4.4 的主实验在两套不同的 Python/NumPy/SciPy 环境下给出相同结果；4.2 的迭代次数与解误差也复现。这说明两份稿子的计算部分没有造假或抄错。
2. **文字层面，问题集中在"结论超出证据"的地方。** G14 的三对角测例、G18 的对称性推理与 4.4.4 三条因果链，都属于"测例/条件不满足却下了强结论"，必须修改。
3. **证据管理需要统一规则。** 两组的计时数字都与 Notebook 保存输出不一致，而且是**有利于结论**的那一次被引用；两份稿子的 4.4 梯度实验又是同一组输入（见 III.1）。这两点在整合前必须澄清：既不重复计数，也不把整节判成"同源"。
4. **本组的增量**：补了复数步长微分这一路（A 组因缺 PyTorch 未做自动微分），为 4.4.4 的三条论断各提供了一个可手算的反例，并把"4.4 里只有梯度这一项重合、其余各自独立"用逐位相同的数据确认下来。

**局限**

1. 未安装 PyTorch，"自动微分库交叉验证"这一路仍未完成；若课程要求必须用库，需另补。
2. 未复现习题、编写报告与图片文件；未涉及 LoRA 训练效果、真实数据集上的 PCA 与大规模性能。
3. 计时数据只代表本机单次运行，本报告不据此给出任何加速比结论。
4. 未获得 A 组的完整 commit SHA，按工作区当前版本核对；若文件更新，需按修正清单复测。
