# 02 Notebook教材写作与验收

## 第一次写作先做这个小练习

按[环境教程](01-环境安装与运行.md)从课程助手打开JupyterLab。在左侧进入第一章并打开A组-实验.ipynb；选中一个单元，工具栏“+”可以新增单元，类型下拉框选择Markdown或Code。Markdown写标题、正文与公式，Code写Python；Shift+Enter运行，Ctrl+S保存。

修改后先“Kernel → Restart Kernel and Run All Cells”，确认顺序执行成功，再保存。逐项核对实际输出与推导、参考值和容差，并记录结果；终端命令不写进普通Code单元。关闭浏览器不会替你上传GitHub，上传需要按提交教程操作。

## 按本章四节填内容：不用自己重新搭框架

每章已经按4节×2学时排好。先在[模板入口表](../模板/README.md)找到本章，平时在JupyterLab左侧进入对应章节，打开A组-实验.ipynb即可。

1. 先读开头的核心问题、三个核心概念和四节安排，找到如“2.1 插值与Runge现象”的标题。
2. 双击该节Markdown单元，把“【待填写】”换成自己的概念讲解、手动推导和实验方案；尚未完成的提示暂时保留。
3. 按顺序填写下方“输入与独立参考”“方法实现与运行”“误差图表与比较”三个Code单元。它们现在只显示“未完成”，要用自己的实际代码替换，不能把显示提示当作实验通过。
4. 若本节有“已有起步实验”，先读懂并运行，按提示补齐缺少的部分。第6章的解析反例不是网络训练，第8章的POD重构不是时间预测。
5. 在本节“实际运行记录”中解释输出，不只是贴图；用独立参考说明误差，写出适用条件和未解决的问题。
6. 打开同章A组-正文.md，按相同节号整理连贯讲解，引用Notebook结果；两份文件共有的公式、参数、结论要一致。
7. 将四节对应的题目和答案填入A组-习题.md、A组-习题参考解答.md，再更新本次角色的报告和AI对话记录。

每节的子标题是填写栏，不另占课时。不要把标为选读的主题全部变成必做项目。需要自动微分或训练库时，按[补充安装说明](06-补装Python库与记录依赖.md)在终端手动安装并记录实际版本；模板本身不下载模型、不启动训练。

## 一个Notebook应当像一章教材

按“图片或漫画导入 → 先作预测 → 学习目标 → 问题定义和假设 → 数学推导 → 算法 → 实验 → 误差分析 → 回答开场问题 → 练习 → 来源与局限”组织Markdown与代码。先解释代码为何存在，再给出实现，最后解释输出代表什么。

Notebook中的公式可使用 `$...$` 与 `$$...$$`。图片使用相对路径，如 `ABC共用-图片/convergence.png`。起步实验直接在代码中生成输入；需要真实外部文件时，在正文说明获取方法、来源和实际文件位置，不依赖预留的数据目录。从JupyterLab文件列表打开本章Notebook后，用 `from pathlib import Path; print(Path.cwd())` 查看当前工作目录，再用相对路径读取文件；不要写自己电脑专用的绝对路径。

## 开头的图片和故事怎么写

八章已经放好导入图。打开本章A组-实验.ipynb，第一个Markdown单元就是“图 → 情境 → 问题 → 数学解释”。双击单元可编辑，Shift+Enter预览。图片在本章的ABC共用-图片目录中，写法如下：

```markdown
![用一句话描述图片中的现象和疑问](ABC共用-图片/A-章节导入.svg)

*图1-1：图片标题。概念示意，非实测结果。*
```

先用80—150字讲清情境，再提出一个带有具体条件、可以手算或用代码检验的问题。读者先写预测，随后阅读推导、运行实验，最后在“回到开场问题”中用证据回答。正文和Notebook的图意、参数与结论应当一致。

趣味不等于夸张结论。例如“地图之外”表示训练范围之外需要重新验证，不表示一定失败；“方程残差为零但边界不满足”是解析反例，不是神经网络训练结果。标出比喻的适用范围，真实结果只使用自己运行并核对的输出。更换图片和复制模板的步骤见[模板使用说明](../模板/README.md)。

## 可复现要求

- 从干净内核顺序执行；不依赖曾经运行但已删除的变量。
- 随机实验固定种子，如 `np.random.default_rng(2026)`，并记录多个种子的验证结果。
- 所需小数据提交并登记来源；较大数据提供生成/下载脚本、校验值和精简测试样本。
- 默认实验控制在CPU可运行的规模；记录运行耗时，训练扩展需与助教约定预算。
- 不使用交互输入、私有绝对路径或运行时临时安装依赖。
- 用解析解、独立算法、守恒量或高精度值建立预期；解释容差为何合理。

`np.testing.assert_allclose(actual, expected, rtol=..., atol=...)` 的绝对容差和相对容差需对应尺度。接近零的量尤其需要明确绝对误差判断。

## 人工核验与报告

| 角色 | 亲自核验什么 | 记录在哪里 |
| --- | --- | --- |
| A | 从新内核运行全部单元，核对公式、引用、实验和习题 | 编写报告 |
| B | 依据独立预期，在新环境复现，比较参考解、容差与实际输出 | 验证报告与修正清单 |
| C | 核验假设、边界、反例和A/B可能共同遗漏的问题 | 批判报告、手动推导与AI陷阱 |

只有Markdown说明、尚未编写验证代码的Notebook，仍是待完成模板。报告如实写明已运行、未运行和未能判断的部分。

## 怎样把输出保存到最终教材

亲自运行结束并核对后，按Ctrl+S保存Notebook，数值和图表输出才会写入.ipynb文件。生成HTML时使用这些已保存输出。如果没有运行、没有保存，或把输出清空后保存，生成的网页也不会有相应结果。源码和结果有变化时，应重新运行、核对、保存，再重新生成网页。

## 故意错误如何写进教材

保留错误公式并用断言证明它失败，例如断言“错误算法误差大于某阈值”；若展示预期异常，用 `try/except` 捕获具体异常并断言确实触发。演示故意错误时解释预期行为，避免无说明的报错打断后续运行。不能靠隐藏单元或跳过代码来声称实验成功。

## 习题与来源

每章至少包括概念/推导、实现/数值验证、陷阱辨析三类题目，配套参考解答和验收标准。公开仓库中答案文件同样公开；学生版目录不展示答案只是阅读安排。

逐条记录引用的作者、标题、版本、页码或章节、链接及支撑的主张。AI生成的参考文献必须人工核对真实存在。不能只贴一段AI回复充当教材来源。
