# 02 Notebook教材写作与验收

> 当前提交路线：按[03](03-GitHub协作与提交.md)在GitHub网页选择本组任务分支，用Add file上传。本机保存和网页分支选择是两件事；本页“任务分支”指网页接收上传的分支，不要求先在终端切分支。正文命名用 `A1-G编号-正文` / `A2-G编号-正文`；其他成果文件沿用现有名称。

> 文件命名：下面涉及 `A2组-`、`B2组-`、`C2组-` 的路径为第2组示例；第1组改成本章A1及自己的G编号；正文以外文件仍沿用A1组等前缀。第一次按[模板复制与命名说明](#模板复制与命名)从本章 `模板/` 复制 `模板-*` 原件到同章 `工作/` 并改名；后续编辑 `工作/` 中已有的本组副本。先查章节README，不能自行选择组号。

## 模板复制与命名

教材模板统一放在 `教材/第xx章-章名/模板/`；本教程只说明怎样使用，不另存一套模板。

### 先分清模板、组稿和整合稿

| 文件类型 | 例子 | 谁来编辑 |
| --- | --- | --- |
| 原始模板 | 本章 `模板/模板-A组-正文.md`、`模板/模板-B组-验证报告.md` | 保留原件，供各组复制 |
| 小组成果 | 本章 `工作/A1-G20-正文.md`、`工作/B2组-验证报告.md` | 对应小组填写自己的副本 |
| 教材整合稿 | 本章 `工作/整合-正文.md`、`工作/整合-实验.ipynb`、`工作/整合-习题.md`、`工作/整合-习题参考解答.md` | D/E按六组讨论结论整合，并保留来源与复核证据 |

“模板”统一放在文件名最前面，方便识别。A/B/C是本章角色；G编号是固定的实际学生小组。每章同一角色有两组，原分组表从左到右分别叫第1组、第2组。**不能自己挑1或2**，应查[章节分工表](../协作管理/章节分工表.md)。同一A1组称呼在不同章节可能对应不同G组；需要跨章引用时，同时写章号和G编号。

例如G22在第01章叫A2组，在第02章叫B2组，在第03章叫C2组；不是永久叫A2。公开只填组别，不写姓名或GitHub账号。D1—D3、E1—E3沿用原名；第05章“寻优的旅程”沿用既定的第五章ABC分工，由E1—E3共同整合，截止日期按后四章执行。

### 在JupyterLab里复制到工作目录并改名

每章根目录只保留入口README以及 `模板/`、`工作/` 两个文件夹。`模板/` 保存原件；`工作/` 是本章所有小组写作的位置；`工作/图片/` 放实际使用的图片。所有可填写的模板均放在对应章节的 `模板/` 中。

下面用**第01章G22承担A2组**举例，其他小组先查章节README换成自己的组号：

1. 完成[环境安装](01-环境安装与运行.md)，按[Git提交教程](03-GitHub协作与提交.md)创建自己的任务分支，再启动JupyterLab。
2. 在左侧文件列表依次双击 **教材 → 第01章-误差的代价**，先读README里的组名表，再双击 **模板**。
3. 找到 `模板-A组-正文.md`，在**左侧文件名**上右键，选择 **Copy（复制）**。这是复制文件，不是打开后复制文字；不要选Cut（剪切）。
4. 点击左侧列表上方路径中的 **第01章-误差的代价** 返回本章，再双击 **工作**。在文件列表空白处右键，选择 **Paste（粘贴）**。若菜单不显示，可在文件列表内选中文件后按Ctrl+C（Mac为Command+C），进入目标目录后单击列表空白处，再按Ctrl+V（Mac为Command+V）。
5. 此时 `工作/` 出现 `模板-A组-正文.md`。右键这份新副本 → **Rename（重命名）**，改成 `A2-G22-正文.md`，按Enter。保留 `.md`；Notebook保留 `.ipynb`。不要只改页面里的标题，不要改成 `.md.txt`。回看 `模板/`，原件应仍然存在。
6. 重复第3—5步，复制本角色其余文件。A组6份、B组5份、C组5份，清单见章节README；本次只复制自己的角色。若 `工作/` 已有本组副本，直接继续编辑，不再复制覆盖旧记录。若粘贴时提示同名文件，先取消并核对，不选择覆盖。
7. 在 `工作/` 打开副本填写。Markdown用右键 **Open With → Editor**；Notebook直接双击。把标题和基本信息改为本章组名、实际G编号与任务范围。`工作/` 和 `工作/图片/` 中的 `.gitkeep` 是空目录占位，留着即可，不用打开、填写或运行。
8. **同步副本里的链接。** 例如 `A2-G22-正文.md` 中 `[实验](模板-A组-实验.ipynb)` 改为 `[实验](A2组-实验.ipynb)`。报告中的AI对话链接也改为本组文件。Notebook里的Markdown单元同样检查。只修改自己的副本，不要全仓库替换。
9. **复制实际用到的模板插图。** 第01—04章、第06—08章的插图在本章 `模板/图片/A-章节导入.svg`。用同样的Copy/Paste操作，将图复制到本章 `工作/图片/`；保持这个文件名时，副本中的 `图片/A-章节导入.svg` 可直接使用。图已经存在就先核对内容，不重复覆盖。若要自行改图，另存为如 `A2组-章节导入.svg`，再将自己的正文和Notebook图片链接改成 `图片/A2组-章节导入.svg`。第05章尚无现成导入图，三格分镜写在 `模板/模板-A组-正文.md` 和实验Notebook模板中，按分镜自行绘图，成图放 `工作/图片/`；`模板/图片/README.md` 另有图片存放说明。
10. 自己新增的结果图放在 `工作/图片/`，如 `A2组-误差曲线.png`；在 `工作/A2-G22-正文.md` 中写 `![误差曲线](图片/A2组-误差曲线.png)`。图片路径从当前文件所在目录出发，不写自己电脑的绝对路径。
11. 引用其他组时写实际目标：B2若复现本章A1和A2，分别写两份实验文件路径和各自完整commit；不要把所有A链接都改成A2。同章成果都在 `工作/`，可直接用文件名链接；引用其他章时要明确章号和目标路径。只审一部分就明确范围。
12. 保存，Notebook按 **Kernel → Restart Kernel and Run All Cells** 运行并核对输出，再保存。按Git教程提交本组 `工作/` 中的副本及必要图片；不要把模板运行后的偶然变化当作本组成果提交。

完成后，例子的源文件是 `教材/第01章-误差的代价/工作/A2-G22-正文.md`，原件仍是 `教材/第01章-误差的代价/模板/模板-A组-正文.md`。**编辑工作里的副本，保留模板里的原件。**

### 同一章先独立完成，再讨论整合

**A1、A2各自独立完成本章四节的完整版本**，包括正文、实验Notebook、习题与解答、编写报告和AI对话记录；不能预先分成两半，也不能把另一组的工作算作本组完成。两份初稿完成并经过B/C验证后，本章A1、A2、B1、B2、C1、C2共同讨论每部分采用哪组版本，必要时综合改写，再由D/E按讨论结论整合成一章。

例如第01章，A1和A2都要写1.1—1.4并完成配套实验与习题。讨论后可以采用A1的1.1讲解、A2的1.2实验，再重写连接两节的过渡；这些选用决定发生在两份完整初稿之后。B1/B2、C1/C2分别保留自己的证据，注明审过哪组的哪些内容及完整SHA，不能把编号理解成B1只审A1、B2只审A2。各组AI对话仍分开保存。

讨论结果写在现有编写报告或整合PR中：列出部分、来源小组与SHA、采用或综合改写的理由、B/C证据和未决问题。保留两份原稿，整合稿另存为 `整合-*`；合并后的公式、参数、代码与结论要一致，Notebook重新运行。详细操作见[08操作指南](08-各组具体操作指南.md#七本章六组怎样讨论选用版本)。

整合组汇总为一份完整教材，保留来源与组别，不能直接覆盖一组的文件来冒充合并。若其他分支上已有人使用旧的 `A组-正文.md` 等名字，先保留其修改，再协调迁移到正确小组副本；不要以新模板覆盖已有工作。

## 第一次写作先做这个小练习

按[环境教程](01-环境安装与运行.md)从课程助手打开JupyterLab。在左侧依次进入“教材 → 第01章-误差的代价 → 工作”，打开已复制并改名的 `A2组-实验.ipynb`；第01章B角色尚未保存独立推导时，继续用环境教程中的临时Notebook练习，不提前看A实现。选中一个单元，工具栏“+”可以新增单元，类型下拉框选择Markdown或Code。Markdown写标题、正文与公式，Code写Python；Shift+Enter运行，Ctrl+S保存。

修改后先“Kernel → Restart Kernel and Run All Cells”，确认顺序执行成功，再保存。逐项核对实际输出与推导、参考值和容差，并记录结果；终端命令不写进普通Code单元。关闭浏览器不会替你上传GitHub，上传需要按提交教程操作。

正式填写本章前，先按[03提交教程](03-GitHub协作与提交.md)从更新后的main建立自己的任务分支。第一次练习产生的文件改动先保留并查看，不直接上传为整章成果。具体A/B/C/D/E分别改什么，见[08操作指南](08-各组具体操作指南.md)。

## 先学会编辑三类文件

### 文字文件.md：正文、习题、报告和AI对话

1. 启动JupyterLab后，在左侧文件列表双击“教材”，再双击自己负责的章节，进入 `工作`。
2. 找到要改的文件，如`A2-G22-正文.md`或`B2组-验证报告.md`。右键文件名，选择 **Open With → Editor**（文本编辑器）。如果双击只显示排版后的文章、无法输入文字，也用这个方法打开编辑器。
3. 点击文字区域，在本组副本里将“待填写”换成实际内容。A1、A2各自完成全章四节，组内可以安排成员分工；B/C填写本组实际核验的内容。保留已有证据与修订记录，不改别组副本。按Ctrl+S（Mac用Command+S）保存。
4. 想看排版时，右键同一文件，用 **Open With → Markdown Preview** 打开预览；不同界面名称可能显示为Markdown预览。编辑器写内容，预览页看效果，两个标签可以同时开。
5. Markdown文字文件没有代码内核，里面的代码块只用于展示，不会因为Ctrl+S而执行。需要实际运行的代码放在对应Notebook中。

常见写法如下。复制内容时不复制包住示例的最外层三个反引号；内部的`#`、`-`等符号要保留：

```markdown
## 1.1 浮点数与舍入误差

这里写一段解释。段落之间空一行。

### 一个例子

- 说明输入是什么。
- 说明结论成立的条件。

公式写作 $a+b$，另起一行的公式可用 $$a+b=c$$。
```

`#`、`##`、`###`分别是一级、二级、三级标题，符号后留一个空格。不要把整份正文贴进一个Python Code单元；出现SyntaxError不意味着数学公式错，可能只是放错位置。[JupyterLab文件编辑说明](https://jupyterlab.readthedocs.io/en/stable/user/files.html)

### 实验文件.ipynb：Markdown单元和Code单元

1. 双击已有Notebook，例如A2组-实验.ipynb。弹出选择内核时选 **Python 3 (course-2026)**。
2. 单击想修改的单元。文字显示为排版效果时，双击它进入编辑。工具栏的类型下拉框应是Markdown；写代码时选择Code。
3. 选中单元后点击工具栏“+”，通常在当前单元下方插入新单元；再选择类型。不要先创建第二个同名实验文件。
4. 按Shift+Enter执行当前单元：Markdown显示排版，Code计算并显示输出。Code左边的`[*]`表示忙，数字表示一次执行的编号；编号不是得分或公式编号。
5. 先按从上到下的顺序运行。只运行最后一格出现`NameError`，可能前面的变量定义还没执行；不要复制一大段重复定义掩盖问题。
6. 提交前用 **Kernel → Restart Kernel and Run All Cells** 从空内存重新执行。重启会丢掉未存成文件的内存变量，已保存的文字和代码不会因此消失。
7. 核对实际数值和图表，再Ctrl+S；保存后的输出才会进入网页教材。红色Traceback要分析，不能只清空输出假装通过。

若要删除自己误加的单元，可用 **Edit → Delete Cells**，先确认选择范围；误删且尚未进行其他操作时可用 **Edit → Undo Cell Operation**恢复。不要用删除单元来删掉另一组证据。

### 图片：放到本章工作/图片，再在文中引用

1. 在JupyterLab依次进入本章的 `工作 → 图片` 文件夹，点击文件列表上方的上传按钮，或把本机图片拖进左侧文件列表。上传到这里仍只是复制到本机课程目录，没有上传GitHub。
2. 文件名使用本章组名与用途，如 `A2组-误差曲线.png`。需要沿用导入图时，先从本章 `模板/图片/` 复制到 `工作/图片/`。要修改导入图就另存为 `A2组-章节导入.svg` 并修改自己的链接，不覆盖别组使用的图片。
3. 回到 `工作/` 中的正文或Notebook的Markdown单元，写 `![误差随步长变化](图片/A2组-误差曲线.png)`，保存并预览。图片相对路径以当前文件所在目录为起点。
4. 在图下注明含义、参数、来源，以及它是实测图还是概念示意。提交时正文/Notebook和图片文件都要通过Add file上传到对应目录；只上传正文会让别人看到缺图。

`工作/图片/` 初始只有空的 `.gitkeep`，不是已经附带全部模板插图；只复制本组实际用到的图。学生自行制作的PNG/JPG也能使用，不要求安装绘图软件或重新生成全部导入图。

## 按本章四节填内容：不用自己重新搭框架

每章已经按4节×2学时排好。先在[模板入口表](#模板复制与命名)找到本章，平时在JupyterLab左侧进入对应章节的 `工作/`，打开 `A2组-实验.ipynb` 即可。

1. 先读开头的核心问题、核心概念和四节安排，找到如“2.1 插值与Runge现象”的标题。第05章有四个核心概念，其余七章各有三个。
2. 双击该节Markdown单元，把“【待填写】”换成自己的概念讲解、手动推导和实验方案；尚未完成的提示暂时保留。
3. 第01—04章、第06—08章按顺序填写下方“输入与独立参考”“方法实现与运行”“误差图表与比较”三个Code单元。第05章提供四段起步演示及扩展提示，按对应实验任务补齐代码。占位单元只显示“未完成”，要用自己的实际代码替换，不能把显示提示当作实验通过。
4. 若本节有“已有起步实验”，先读懂并运行，按提示补齐缺少的部分。第6章的解析反例不是网络训练，第8章的POD重构不是时间预测。
5. 在本节“实际运行记录”中解释输出，不只是贴图；用独立参考说明误差，写出适用条件和未解决的问题。
6. 打开同章 `工作/A2-G22-正文.md`，按相同节号整理连贯讲解，引用Notebook结果；两份文件共有的公式、参数、结论要一致。
7. 将四节对应的题目和答案填入A2组-习题.md、A2组-习题参考解答.md，再更新本次角色的报告和AI对话记录。

每节的子标题是填写栏，不另占课时。不要把标为选读的主题全部变成必做项目。需要自动微分或训练库时，按[补充安装说明](05-补装Python库与记录依赖.md)在终端手动安装并记录实际版本；模板本身不下载模型、不启动训练。

## 一个Notebook应当像一章教材

按“图片或漫画导入 → 先作预测 → 学习目标 → 问题定义和假设 → 数学推导 → 算法 → 实验 → 误差分析 → 回答开场问题 → 练习 → 来源与局限”组织Markdown与代码。先解释代码为何存在，再给出实现，最后解释输出代表什么。

Notebook中的公式可使用 `$...$` 与 `$$...$$`。图片使用相对路径，如 `图片/A2组-误差曲线.png`。起步实验直接在代码中生成输入；需要真实外部文件时，在正文说明获取方法、来源和实际文件位置，不依赖预留的数据目录。从JupyterLab文件列表打开本章 `工作/` 中的Notebook后，用 `from pathlib import Path; print(Path.cwd())` 查看当前工作目录，再用相对路径读取文件；不要写自己电脑专用的绝对路径。

## 开头的图片和故事怎么写

第01—04章、第06—08章的导入图在各章 `模板/图片/`。第05章尚无现成导入图，漫画分镜在正文和实验Notebook模板中，按分镜自行绘图；`模板/图片/README.md` 说明图片存放方法。先把实际使用的图复制到同章 `工作/图片/`。打开本章 `工作/A2组-实验.ipynb`，第一个Markdown单元就是“图 → 情境 → 问题 → 数学解释”。双击单元可编辑，Shift+Enter预览。沿用模板插图文件名时，写法如下：

```markdown
![用一句话描述图片中的现象和疑问](图片/A-章节导入.svg)

*图1-1：图片标题。概念示意，非实测结果。*
```

先用80—150字讲清情境，再提出一个带有具体条件、可以手算或用代码检验的问题。读者先写预测，随后阅读推导、运行实验，最后在“回到开场问题”中用证据回答。正文和Notebook的图意、参数与结论应当一致。

趣味不等于夸张结论。例如“地图之外”表示训练范围之外需要重新验证，不表示一定失败；“方程残差为零但边界不满足”是解析反例，不是神经网络训练结果。标出比喻的适用范围，真实结果只使用自己运行并核对的输出。更换图片和复制模板的步骤见[模板使用说明](#模板复制与命名)。

## 可复现要求

- 从干净内核顺序执行；不依赖曾经运行但已删除的变量。
- 随机实验固定种子，如 `np.random.default_rng(2026)`，并记录多个种子的验证结果。
- 所需小数据提交并登记来源；较大数据提供生成/下载脚本、校验值和精简测试样本。
- 默认实验控制在CPU可运行的规模；记录运行耗时，训练扩展需与助教约定预算。
- 不使用交互输入、私有绝对路径或运行时临时安装依赖。
- 用解析解、独立算法、守恒量或高精度值建立预期；解释容差为何合理。

`np.testing.assert_allclose(actual, expected, rtol=..., atol=...)` 的绝对容差和相对容差需对应尺度。接近零的量尤其需要明确绝对误差判断。

## 人工核验与报告

| 角色 | 亲自核验什么 | 记录在哪里 |
| --- | --- | --- |
| A | 从新内核运行全部单元，核对公式、引用、实验和习题 | 编写报告 |
| B | 依据独立预期，在新环境复现，比较参考解、容差与实际输出 | 验证报告与修正清单 |
| C | 核验假设、边界、反例和A/B可能共同遗漏的问题 | 批判报告、手动推导与AI陷阱 |

只有Markdown说明、尚未编写验证代码的Notebook，仍是待完成模板。报告如实写明已运行、未运行和未能判断的部分。

## 怎样把输出保存到最终教材

亲自运行结束并核对后，按Ctrl+S保存Notebook，数值和图表输出才会写入.ipynb文件。生成HTML时使用这些已保存输出。如果没有运行、没有保存，或把输出清空后保存，生成的网页也不会有相应结果。源码和结果有变化时，应重新运行、核对、保存，再重新生成网页。

## 故意错误如何写进教材

保留错误公式并用断言证明它失败，例如断言“错误算法误差大于某阈值”；若展示预期异常，用 `try/except` 捕获具体异常并断言确实触发。演示故意错误时解释预期行为，避免无说明的报错打断后续运行。不能靠隐藏单元或跳过代码来声称实验成功。

## 习题与来源

每章至少包括概念/推导、实现/数值验证、陷阱辨析三类题目，配套参考解答和验收标准。公开仓库中答案文件同样公开；学生版目录不展示答案只是阅读安排。

逐条记录引用的作者、标题、版本、页码或章节、链接及支撑的主张。AI生成的参考文献必须人工核对真实存在。不能只贴一段AI回复充当教材来源。

引用文字、代码、图片或数据时，核查来源与使用许可，不上传未经授权的整本教材或论文扫描件；AI生成的内容同样需要核查。AI生成的图片还需记录工具、提示词、日期、人工修改及来源。教学团队尚未确定全书的最终授权，仓库目前没有正式LICENSE。全书对外发布前，需由教学团队确认文字、代码、图片、数据的许可与所需作者授权；学生不要自行替其他作者作出授权声明。
