# 04 生成与查看整本HTML教材

“生成教材”把各章文字、公式和Notebook的已保存内容排版成网页。“预览”是在自己电脑上打开这套网页。**先在JupyterLab亲自运行实验、核对输出并保存，再生成教材。**

## 1. 使用前提

已经完成[环境安装](01-环境安装与运行.md)，课程根目录能看到course.cmd、course.py和教材目录。生成功能已合并到根目录的course.py中，使用下面的课程助手命令即可，不需要单独的脚本目录。

各章Notebook保存后，保留启动Jupyter的窗口A，在课程根目录另开一个PowerShell作为窗口B。命令输入窗口B，不输入Notebook代码单元。

如果不知道如何打开窗口B：按Win+E进入课程文件夹，点击顶部地址栏（不是右侧搜索框），输入`powershell`并回车。先运行`dir`，能看到course.cmd、course.py和教材目录才继续。Mac/Linux另开终端，先用`cd "$HOME/course-work/course-2026"`进入自己安装时的课程目录；实际位置不同就替换路径。

## 2. 生成HTML：执行完会回到提示符

Windows输入：

```powershell
.\course.cmd build
```

macOS/Linux输入：

```bash
python3.12 course.py build
```

选自己系统的一条执行。等待“构建完成”，输出目录为`教材/_build/html/`。程序按照`教材/_toc.yml`排列章节，读取Markdown、Notebook代码及已保存的输出。

**生成过程不执行Notebook代码。** 网页中没有结果时，先回到Notebook亲自运行并保存，再重新build。生成网页成功只说明排版过程完成，内容正确性由A/B/C和助教核验。[Jupyter Book执行配置说明](https://jupyterbook.org/v1/content/execute.html)

## 3. 预览HTML：这一步会持续占用窗口B

等build完成后，Windows输入：

```powershell
.\course.cmd preview
```

macOS/Linux输入：

```bash
python3.12 course.py preview
```

保持窗口B打开，再打开浏览器，在地址栏输入[http://127.0.0.1:8000](http://127.0.0.1:8000)。这是自己电脑上的教材页面；JupyterLab通常使用8888端口，两者不是同一个页面。

看完后回到窗口B按Ctrl+C停止预览，直到再次看到提示符。关闭网页标签不等于停止服务。

## 4. 修改后再生成，按这个顺序

1. 回到JupyterLab修改并保存源文件；代码或结果有变化时先运行、核对再保存。
2. 回到正在preview的窗口B，按Ctrl+C，等待出现`PS ...>`。这时窗口B才可以继续输入命令。
3. Windows运行`.\course.cmd build`（Mac/Linux运行`python3.12 course.py build`），等成功结束。失败时先处理第一条具体错误，不把上一次留下的旧网页当成新结果。
4. 再运行preview，等待终端显示访问地址；浏览器重新打开该地址或刷新。仍显示旧页面时可用Ctrl+F5（Mac用Command+Shift+R）强制刷新。
5. D/E按下表逐项查看，并把实际检查范围与未解决项写进自己的PR。不要勾选没检查的项目。

| 要查看的内容 | 具体怎么做 |
| --- | --- |
| 章节顺序 | 在左侧目录依次点开自己负责的四章，确认标题和前后顺序 |
| 正文与公式 | 检查标题层级、公式显示、符号一致、跨章过渡 |
| 实验结果 | 点实验页，确认已保存的图表和数值出现；是否正确仍需A/B/C证据 |
| 图片与链接 | 点击正文链接，查看每张导入图和结果图；缺图先核对文件名与相对路径 |
| 习题 | 打开习题页，核对题号与正文对应，参考解答另在仓库核对 |
| 未展示的报告 | B/C报告、AI记录和参考解答未列在网页目录是当前安排，不代表文件丢失 |

`教材/_toc.yml`已经配置八章的正文、实验与习题。普通填充内容不需要改它；不熟悉YAML时不要改缩进或随意增删章节。`教材/_ext`随build处理中文插图路径，保留即可。D/E完整整合流程见[08操作指南](08-各组具体操作指南.md)。

## 5. 想交给老师或同学查看

把`教材/_build/html/`整个文件夹压缩后交给对方，保留其中的子目录、样式和图片；只发送index.html会缺少其他页面。对方也可以下载源文件，安装环境后按本教程自行生成和查看。

Windows可按Win+E进入课程文件夹，再依次打开`教材 → _build`，右键`html`文件夹，选择“压缩为ZIP文件”（Windows 10可能在“发送到 → 压缩文件夹”）。这是需要线下分享时的做法；课程GitHub提交仍交源文件和PR，不上传_build或这个压缩包。

需要查看收到的HTML压缩包时，先解压。已经安装课程环境的Windows同学，在课程根目录输入下面命令，将引号中的路径换成实际解压后直接包含index.html的目录：

```powershell
.\.venv\Scripts\python.exe -m http.server 8000 --bind 127.0.0.1 --directory "C:\Users\你的用户名\Downloads\html"
```

然后访问同一本地地址；按Ctrl+C停止。macOS/Linux把Python路径换成`.venv/bin/python`，并换成自己的解压目录。127.0.0.1表示当前电脑，直接把这个地址发给别人并不能共享你的网页。

## 6. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 提示没有HTML教材 | 先build，等成功后再preview |
| 提示找不到course.cmd或course.py | 回到能看到这些文件的课程根目录 |
| 提示找不到jupyter-book | 按环境安装教程，用现有.venv中的Python补装jupyter-book与sphinx |
| 网页没有数值、图表，或内容是旧的 | 在JupyterLab运行、核对并保存，再build |
| 网页缺少章节或图片 | 核对_toc.yml中的路径及图片相对路径 |
| 8000端口被占用 | 停止之前的预览，或运行preview --port 8001并访问终端显示的新地址 |
| build失败 | 阅读第一条具体错误，修复后重试，不把旧网页当作新结果 |

生成结果是HTML网页教材，源Notebook仍可在JupyterLab中编辑运行。当前不需要学习整本PDF排版或网站部署。
