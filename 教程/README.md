## 按本次任务选择路线

先完成01的安装。安装练习结束后，**正式写作前先按03建立工作分支**，再用02编辑文件，按08完成本次角色任务，最后回03提交。不要直接在main上写整章作业。

| 本次角色 | 打开08中的哪一节 | 还需要的专门教程 | 最终交什么 |
| --- | --- | --- | --- |
| A：编写 | A组：从初稿到修订 | 02；额外依赖看05 | 正文、实验、习题与解答、编写报告、A的AI记录 |
| B：验证 | B组：先独立，再复现 | 06 | 独立推导、验证Notebook、验证报告、修正清单、B的AI记录 |
| C：批判 | C组：核验A和B的结论 | 06的固定版本方法 | 手动推导、人工复核Notebook、批判报告、AI陷阱、C的AI记录 |
| D：前四章整合 | D/E组：把章节整理成教材 | 04 | 前四章整合修改与PR中的整合说明 |
| E：后四章整合 | D/E组：把章节整理成教材 | 04 | 后四章整合修改与PR中的整合说明 |

不知道自己属于哪个角色，先在[正式章节分工表](../协作管理/章节分工表.md)找到G编号。同一个ABC小组在三个不同章节担任不同角色；D/E专门整合。日期见[进度安排](../协作管理/进度安排.md)。

## 三个最容易混淆的操作

- **Ctrl+S**：只保存当前电脑上的文件；尚未上传。
- **commit、push、PR**：依次保存本地版本、上传到自己的分支、申请合并到课程主分支。具体按03做。
- **build、preview**：在本机生成和查看网页；不会上传GitHub，也不会替你运行实验、检查公式。

Jupyter的窗口A保持运行，其他命令在空闲窗口B输入。preview也会占用一个终端；要继续输入命令，先Ctrl+C停止它，或另开终端进入同一课程文件夹。
