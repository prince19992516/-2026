# 01 从零安装环境、打开Notebook并完成第一次检查

本教程面向没有编程项目经验的同学。推荐先完成 **Windows + Python 3.12 + 本仓库课程助手** 这一条路线。不要同时安装Conda、Docker和多个环境；它们属于[进阶替代方案](06-进阶环境与原始命令.md)，不是入门前置要求。

已经打开JupyterLab却不知道如何继续？先看[两个窗口的操作图解](00-已经打开JupyterLab接下来怎么办.md)。

## 1. 先认识五个名称

| 名称 | 你可以怎样理解 | 在哪里操作 |
| --- | --- | --- |
| GitHub | 课程文件在网上的仓库 | 浏览器访问github.com |
| Git | 把本地修改保存为版本并上传的工具 | PowerShell中输入git命令 |
| Python | 运行本课程代码的程序 | 本课程固定3.12系列 |
| JupyterLab | 在浏览器里编写教材的编辑界面 | 由本机终端启动，通常是127.0.0.1地址 |
| Notebook内核 | 真正执行一个Notebook中代码的Python进程 | 在JupyterLab中选“Python 3 (course-2026)” |

`.venv` 是本课程专用的Python环境文件夹。不同课程依赖可能不同，因此集中放在这里；不要复制同学的 `.venv`，也不要将它上传GitHub。

**命令的输入规则：** 本教程每个终端命令单独执行一次，按回车，等结果再继续。不要把多条命令接成一行。代码块外的 `PS C:\...>`、`$` 等提示符不是命令，不要一起复制。

## 2. Windows首次安装：先装两个软件

适用于Windows 10/11常见64位电脑。若是ARM设备、学校受管设备或不能安装软件，先联系助教选择兼容方案。

### 2.1 安装Python 3.12
1. 打开 [Python 3.12.10官方发布页](https://www.python.org/downloads/release/python-31210/)。它提供Windows传统安装器，也与本仓库3.12基线兼容；已装可用的3.12.x无需重复安装。
2. 在页面Files部分下载 **Windows installer (64-bit)**，不要下载embeddable package或源代码压缩包。
3. 运行安装器，勾选 **Add python.exe to PATH**；保留Python Launcher（`py`）选项，再选择Install Now。通常个人安装即可，不要求以管理员身份运行课程。
4. 安装结束后关闭旧终端，再从开始菜单搜索 **PowerShell** 并打开。
5. 输入下面这一行并回车：

```powershell
py -3.12 --version
```

**成功标志：** 输出 `Python 3.12.x`。如果报“找不到py”或没有3.12，先处理，不要跳到下一步。这里不是必须使用系统默认 `python` 指向的版本；你的默认Python是3.14也没有关系。

### 2.2 安装Git
从 [Git官方安装入口](https://git-scm.com/install/windows) 下载并安装Git for Windows，初学者可以保留默认选项。关闭旧PowerShell再开一个新窗口，输入：

```powershell
git --version
```

**成功标志：** 输出以 `git version` 开头。GitHub账号用于后续提交作业；公开仓库下载不需要登录。

## 3. 下载课程：第一次才clone

### 3.1 新同学，没有课程文件夹
在文件资源管理器中创建并打开一个保存课程的父文件夹，例如 `D:\Courses`（没有D盘就使用自己的文档文件夹）。点击文件资源管理器顶部地址栏，输入 `powershell`，回车。新终端就在这个文件夹里。

输入下面命令，并等待下载结束：

```powershell
git clone https://github.com/prince19992516/-2026.git course-2026
```

然后进入下载好的课程目录：

```powershell
cd course-2026
```

确认位置：

```powershell
dir
```

**成功标志：** 能看到 `course.cmd`、`course.py`、`README.md`、`教材`、`环境`。这一层就是后文说的“仓库根目录”。不是 `教材` 子文件夹，也不是下载目录的上一层。

### 3.2 已有课程文件夹，包括助教的2026文件夹
不要再往已有目录里面clone一份。在文件资源管理器打开已有文件夹，用地址栏启动PowerShell，先查看状态：

```powershell
git status
```

如果显示工作区干净（`working tree clean`），且当前分支是main，可更新：

```powershell
git pull --ff-only origin main
```

如果有未提交文件或正在自己的作业分支上，先按[提交教程](02-GitHub协作与提交.md)保存工作，再更新；不要使用reset或强推来“清空错误”。看不到 `course.cmd` 时，可能还没更新到新版，或当前目录不对。

用GitHub的Download ZIP也能获得文件并运行实验，但ZIP不含Git历史，不能直接按提交教程推送。需要提交作业的同学优先使用clone。

## 4. 安装课程环境：首次做一次

确认PowerShell所在位置能看到 `course.cmd`，输入：

```powershell
.\course.cmd setup
```

**这一步会做什么：** 使用Python 3.12创建 `.venv` → 安装 `环境/requirements.txt` 中的依赖 → 注册课程Notebook内核 → 检查版本、导入和依赖兼容性。

**你会看到什么：** `Collecting`、`Downloading`、`Installing` 等安装日志，可能持续数分钟到更久，取决于网速。不要因为还没有弹出浏览器就认为失败。安装期间不要继续粘贴后续命令。

**完成标志：** 输出“环境检查通过”和“安装完成”，最后重新出现 `PS ...>` 提示符。若出现“本步未成功”或 `ERROR`，先看本文报错表。断网后可恢复网络并重新运行同一条setup命令，已安装内容会被复用。

检查环境可以单独运行：

```powershell
.\course.cmd doctor
```

它应打印本课程 `.venv` 的路径、Python 3.12.x和各依赖版本，最后显示“环境检查通过”。安装成功不等于实验已经验证；下一步做一次运行检查。

**也可以不用输入助手命令：** 在文件资源管理器双击 `course.cmd`，输入数字 `1` 并回车，完成安装；输入 `6` 检查环境，输入 `0` 退出菜单。首次双击前也必须先安装Python 3.12与Launcher。

## 5. 在启动Jupyter前先做一次检查

在同一个空闲PowerShell中运行：

```powershell
.\course.cmd check
```

等待“检查命令全部结束”。初始版本的Notebook汇总应为：

```text
{"passed": 9, "failed": 0, "placeholder": 16}
```

9个passed对应8章起步实验和1个实验模板；16个placeholder是8章尚待学生完成的B/C Notebook。以后补充实验后数量会变化，重点是 `failed` 应为0。结构与陷阱格式检查通过，不代表学生报告已完成或数学结论已证明。

## 6. 窗口A：打开并使用JupyterLab

现在运行下面这一条命令：

```powershell
.\course.cmd lab
```

**从这一步起，窗口A被持续占用是正常的。保持窗口A打开。后面的检查命令不在窗口A的日志中输入。**

浏览器通常会自动打开JupyterLab。若没有弹出，找终端输出中带 `/lab?token=...` 的 `http://127.0.0.1:...` 或 `http://localhost:...` 链接，完整复制到浏览器地址栏。token是本机服务访问凭证，不要发到公开仓库；不要将链接中的文字逐段改写。

### 6.1 打开第一章
1. 在JupyterLab左侧文件列表双击 `教材`。
2. 双击 `第01章-误差`。
3. 双击 `实验.ipynb`。不要创建一个空文件来代替它。
4. 如果询问内核，选择 **Python 3 (course-2026)**。已有Notebook可通过 **Kernel → Change Kernel** 选择课程内核。
5. 点击 **Kernel → Restart Kernel and Run All Cells**，确认重启并运行。

不同语言界面的菜单文字可能翻译为“内核”“重启内核并运行所有单元”。运行时单元左侧可能显示 `[*]`，完成后变为数字 `[1]` 等。第一章应输出 `naive` 为0、`stable` 和 `reference` 约为 `5e-9`，且没有红色Traceback。

### 6.2 如何写文字、公式和代码
点击工具栏“+”增加单元；通过工具栏下拉框选择 **Markdown** 或 **Code**。

Markdown单元输入：

```markdown
## 我对本实验的解释
绝对误差为 $|\hat{x}-x|$。
```

Code单元输入（以下是Python代码，才放进Notebook）：

```python
import sys
print(sys.executable)
```

选中单元按 `Shift+Enter` 运行。输出的Python路径应属于课程 `.venv`。按 `Ctrl+S` 保存。这里保存的是本机文件，**并没有上传到GitHub**；上传操作见提交教程。

不要把 `git pull`、`.\course.cmd check`、`python -m jupyterlab` 等终端命令放进普通Code单元，也不要把Markdown标题当作Python程序运行。

## 7. 窗口B：Jupyter开着时如何检查

1. 在浏览器保存Notebook，暂时停止编辑待检查文件。
2. 重新在文件资源管理器打开课程根目录。
3. 地址栏输入 `powershell` 并回车，得到第二个终端，即窗口B。也可双击第二次 `course.cmd` 打开另一个助手窗口。
4. 在窗口B输入下面命令；不需要激活环境，助手会自动选择同一个 `.venv`：

```powershell
.\course.cmd check
```

只检查第一章的Notebook时可输入：

```powershell
.\course.cmd check 教材/第01章-误差
```

指定章节时，结构和陷阱格式仍检查全仓库，Notebook执行只检查指定目录。脚本使用独立内核执行磁盘上的已保存文件，不会继承浏览器中尚未保存的变量。若实验写同一输出文件，不要同时在浏览器和检查器中执行它。

结果保存在 `_build/executed/summary.json` 和同目录下的执行版Notebook，源Notebook不被覆盖。点击资源管理器中的 `_build` 查看即可；若只想知道通过与否，先看终端最后汇总。

## 8. 关闭服务与第二天重新打开

当天结束时先在Jupyter保存文件，再回到窗口A按 `Ctrl+C`。若出现是否关闭的询问，输入 `y` 并回车；按提示确认，直到出现命令提示符或回到课程助手菜单。关闭浏览器标签页不会自动关闭服务。

第二天不需要重新安装。进入课程文件夹，打开窗口A，运行：

```powershell
.\course.cmd lab
```

需要检查时再开窗口B，运行 `.\course.cmd check`。只有新电脑、环境损坏或课程依赖更新时才重新执行setup；普通文字修改不需要重装依赖。

## 9. 构建HTML教材（按需，不是每次写作必做）

在空闲的窗口B运行：

```powershell
.\course.cmd build
```

等待“构建完成”并返回提示符，再运行：

```powershell
.\course.cmd preview
```

浏览器打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)。preview现在持续占用窗口B，按 `Ctrl+C` 结束预览；它与Jupyter的8888端口是两个不同服务。完整的获取、查看、发布方式见[构建教程](05-构建与发布教材.md)。

## 10. macOS / Linux完整对应流程

以下命令输入系统Terminal，逐条执行。macOS可从Python官方3.12发布页安装macOS universal2 installer；首次执行 `git --version` 时如提示安装命令行工具，按系统提示完成。Ubuntu 24.04可通过系统包管理器安装 `python3.12`、`python3.12-venv`、`git`；其他发行版请由助教按发行版文档提供命令，不要套用Windows安装器。

先验证：

```bash
python3.12 --version
```

```bash
git --version
```

用 `cd` 进入自己的课程父目录，第一次下载：

```bash
git clone https://github.com/prince19992516/-2026.git course-2026
```

```bash
cd course-2026
```

安装、检查各执行一次，等待每步完成：

```bash
python3.12 course.py setup
```

```bash
python3.12 course.py check
```

窗口A单独启动Jupyter：

```bash
python3.12 course.py lab
```

在新的Terminal窗口B中，用 `cd` 进入同一个课程文件夹，运行：

```bash
python3.12 course.py check
```

需要时分别运行 `python3.12 course.py build`、等待完成后运行 `python3.12 course.py preview`。这些助手命令自动使用 `.venv/bin/python`，**无需在每个新终端source激活**。也可运行 `python3.12 course.py` 打开数字菜单。

## 11. 常见问题：看到什么、先做什么

| 现象 | 原因或判断 | 操作 |
| --- | --- | --- |
| 打开Jupyter后终端不能继续输命令 | 服务持续运行，正常 | 保留窗口A，另开窗口B；不要重装 |
| 找不到course.cmd / course.py | 目录不对或仓库尚未更新 | 在根目录用dir/ls确认文件，再检查版本 |
| py不是内部或外部命令 / 无法识别py | Launcher没装好或终端未刷新 | 关闭重开终端；重新运行Python安装器补装Launcher |
| No suitable Python runtime / 找不到3.12 | 没有对应版本 | 安装3.12，再验证 `py -3.12 --version` |
| `.venv`不是Python 3.12 | 使用了其他版本建环境 | 先保存并关闭所有课程服务；按下面修复步骤处理 |
| pip下载超时、连接失败 | 网络或代理问题 | 恢复网络后重跑setup；联系学校网络支持，不随意关闭证书校验 |
| No module named某包 | 环境不完整或内核错误 | 运行doctor；重新setup；从助手启动并选择课程内核 |
| 激活脚本提示禁止执行 | 使用了Activate.ps1 | 助手不需要激活脚本，直接用 `course.cmd` |
| 出现 `>>>` 提示符 | 进入了Python交互解释器 | 输入 `exit()` 回车，返回PowerShell再输入命令 |
| Notebook报SyntaxError，内容是终端命令 | 输入位置错了 | 删除该命令单元，在终端窗口B运行 |
| Notebook一直是 `[*]` | 计算尚未完成或阻塞 | 等待；明显异常时Kernel → Interrupt，检查代码；必要时Restart |
| AssertionError | 实测与预期不符 | 看失败单元、输入和容差，交B/C分析；不要删断言凑通过 |
| 构建失败 / WARNING变错误 | 引用、执行或目录存在问题 | 找第一条具体错误，修复后重跑build |
| 浏览器无法连接 | 服务没开、已停止或地址/端口错 | 看窗口A实际输出，复制其链接；需要时重新lab |
| 端口占用 | 已有服务运行 | 优先使用原服务；或 `.\course.cmd lab --port 8890` / `.\course.cmd preview --port 8001` |
| token失效 | 使用了旧服务的地址 | 复制当前窗口的完整链接 |
| 保存后GitHub看不到 | 只保存到本机 | 按提交教程commit、push并提交PR |

macOS/Linux的端口命令对应 `python3.12 course.py lab --port 8890` 等。Jupyter端口被占用时也可能自动选择下一个端口，以实际日志为准。

**修复损坏环境：** 先保存Notebook并停止Jupyter、检查器和预览服务。在文件资源管理器把课程 `.venv` 文件夹改名为 `.venv-old`（若已有同名备份，选另一个名字），回到课程目录运行setup重建。不要重命名或删除 `教材`。备份环境不能跟着作业上传，本仓库已忽略 `.venv-*`。

**向助教求助时提供：** 操作系统、运行的完整命令、当前目录、第一条具体报错及后面的Traceback、doctor输出。先删去日志中的token和个人信息。不要只发“不能运行”。
