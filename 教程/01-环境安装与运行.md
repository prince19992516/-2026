# 01 从零安装环境并打开第一个Notebook

本教程面向没有编程项目经验的同学。从安装Python和Git开始，接着自己创建虚拟环境、安装Python库，再打开Notebook。每一步都有输入位置、命令含义和完成标志。

## 0. 电脑上什么都没装，从这里开始

本教程假设电脑只有操作系统和自带浏览器。Windows同学先做第0—8节；Mac或Ubuntu同学先读第1节，再转第9节安装，随后按第5节学习Notebook操作。

先准备能上网的电脑、可收邮件的邮箱，并接通电源。安装软件与下载依赖需要联网，安装完成后的起步实验可在本机运行。浏览器使用系统自带的Edge（Windows）或Safari（Mac）即可。

Windows按 `Win+I` 打开“设置 → 系统 → 关于”，查看“系统类型”：下面Windows路线面向x64电脑。ARM电脑、32位系统或无法安装软件的学校电脑，请助教安排兼容环境；不要混用不同架构的安装包。

本次要准备的东西如下，照顺序做：

| 顺序 | 要准备什么 | 获取方式 | 做到什么才继续 |
| --- | --- | --- | --- |
| 1 | Python 3.12 | 第2.1节，官网下载安装器 | 命令显示Python 3.12.x |
| 2 | Git | 第2.2节，官网下载安装器 | 命令显示git version… |
| 3 | GitHub账号 | 第2.3节，浏览器注册 | 能登录；提交前接受协作者邀请或使用Fork |
| 4 | 课程文件 | 第3节，用Git下载 | 文件夹内看到course.cmd |
| 5 | 虚拟环境、JupyterLab和课程依赖 | 第4节，自己逐条输入安装命令 | 能打开JupyterLab并运行第一个实验 |

PowerShell和文件资源管理器是Windows自带的，不需要下载。JupyterLab在第4节由你用pip安装；初次使用不需要另外安装Anaconda、Docker、VS Code或PyCharm。

### 先练习打开终端

1. 按键盘Windows徽标键，输入 `Windows PowerShell`。
2. 点击搜索结果中的Windows PowerShell，普通方式打开即可；日常课程命令不需要“以管理员身份运行”。
3. 出现蓝色或黑色窗口，末尾类似 `PS C:\Users\你的用户名>`，表示可以输入命令。电脑显示其他用户名正常，不要照抄“你的用户名”。
4. 点击窗口空白处，在光标位置粘贴一条命令，按回车。通常可用 `Ctrl+V` 粘贴；旧版PowerShell也可右键粘贴。
5. 等重新出现 `PS ...>` 才执行下一条。终端显示的文字是输出，不用重新输入；看到报错先处理，不连续粘贴后面的命令。

后面会用到文件资源管理器：按 `Win+E` 打开。地址栏是顶部显示文件夹路径的位置，搜索框在右边，二者不同。在地址栏输入 `powershell` 可在当前文件夹打开终端。

## 1. 先认识五个名称

| 名称 | 你可以怎样理解 | 在哪里操作 |
| --- | --- | --- |
| GitHub | 课程文件在网上的仓库 | 浏览器访问github.com |
| Git | 把本地修改保存为版本并上传的工具 | PowerShell中输入git命令 |
| Python | 运行本课程代码的程序 | 本课程固定3.12系列 |
| JupyterLab | 在浏览器里编写教材的编辑界面 | 由本机终端启动，通常是127.0.0.1地址 |
| Notebook内核 | 真正执行一个Notebook中代码的Python进程 | 在JupyterLab中选“Python 3 (course-2026)” |

`.venv` 是本课程专用的Python环境文件夹。不同课程依赖可能不同，因此集中放在这里；不要复制同学的 `.venv`，也不要将它上传GitHub。

**命令的输入规则：** 本教程每个终端命令单独执行一次，按回车，等结果再继续。不要把多条命令接成一行。代码块外的 `PS C:\...>`、`$` 等提示符不是命令，不要一起复制。

## 2. Windows首次安装：先装两个软件

适用于Windows 10/11常见64位电脑。若是ARM设备、学校受管设备或不能安装软件，先联系助教选择兼容方案。

### 2.1 安装Python 3.12：下载、安装、验证

1. 打开浏览器，点击[Python 3.12.10官方发布页](https://www.python.org/downloads/release/python-31210/)。本教程选它是因为有传统图形安装器，**它不是最新的3.12补丁版**。已安装可用的3.12.x可先运行下面验证命令，通过后跳过重装。
2. 向下找到 **Files** 表格，点击 **Windows installer (64-bit)**。不要点页面顶部的其他版本、Python install manager、embeddable package或源代码压缩包，本教程按传统安装器界面说明。
3. 等下载结束。在Edge按 `Ctrl+J` 打开下载列表，点击该安装文件；也可按 `Win+E`，进入“下载”文件夹，双击 `python-3.12.10-amd64.exe`。
4. 安装第一页先勾选底部 **Add python.exe to PATH**。保留Launcher（`py`）安装选项；选择 **Install Now**，等待进度条完成。这里的PATH让终端能找到软件，暂时不需要手工配置它。
5. 如果出现系统权限提示，核对是刚下载的Python安装器后按系统要求完成；学校电脑没有权限时联系管理员。课程运行本身不需要管理员身份。
6. 看到 **Setup was successful** 表示安装完成，点击 **Close**。若出现“Disable path length limit”，可在拥有权限时启用；它不是本教程成功验证版本的前置条件。
7. 关闭刚才所有PowerShell窗口，再按第0节方式新开一个，输入下面这一行并回车：

```powershell
py -3.12 --version
```

**成功标志：** 显示 `Python 3.12.10` 或其他 `Python 3.12.x`，然后出现新的 `PS ...>`。`x`指补丁号，不是要求输出字母x。默认 `python` 指向其他版本也没关系，下面创建虚拟环境时明确使用3.12。

如果打开安装器只看到Modify/Repair，通常表示已经装过；先验证，不必卸载。若提示找不到`py`，先重开终端；仍不行则重新运行安装器，通过Modify补装Launcher，再验证。若提示找不到3.12，确认下载的版本。**验证未成功时先停在这里，不要继续创建虚拟环境。**

### 2.2 安装Git：下载、安装、验证

1. 在浏览器打开[Git官方Windows安装页](https://git-scm.com/install/windows)。
2. 选择 **Git for Windows/x64 Setup**（常见x64电脑），下载`.exe`安装器；不选Portable压缩版。
3. 浏览器 `Ctrl+J` 找到下载文件，点击打开。阅读安装提示，选择安装位置和组件；一般保留默认选项，逐页点 **Next**，最后点 **Install**。
4. 若出现命令行/PATH选项，保留允许在命令行和第三方软件使用Git的默认项；凭据管理器Git Credential Manager也保留。其他界面随版本略有不同，默认设置足够完成本教程。
5. 完成后点 **Finish**。若自动打开Git Bash或说明网页，可以关闭；本教程Windows命令都在PowerShell输入。
6. 关闭旧PowerShell，重新打开一个，输入：

```powershell
git --version
```

**成功标志：** 输出以 `git version` 开头，后面是安装的版本号。若提示无法识别git，先重开终端；仍不行，重新检查安装和PATH选项。不要在GitHub网页的搜索框输入此命令。

### 2.3 注册GitHub账号，为提交作业准备

1. 浏览器打开[GitHub注册页面](https://github.com/signup)。已有账号直接登录即可。
2. 按页面填写邮箱、密码和用户名，完成网页要求的人机验证及邮件验证。邮箱必须能收信；用户名是之后邀请协作者用的账号名。
3. 按页面提示完成免费账号注册，本课程不要求购买付费套餐。可参考[GitHub官方注册说明](https://docs.github.com/en/get-started/start-your-journey/creating-an-account-on-github)。
4. 登录后打开[课程仓库](https://github.com/prince19992516/-2026)。把自己的GitHub用户名告诉助教；收到协作者邀请后，用被邀请的账号打开邀请链接并接受。
5. 公开仓库可直接下载，账号或权限尚未准备好也可先安装运行。提交前需要写权限或使用Fork，操作见[提交教程](03-GitHub协作与提交.md)。账号密码用于网页登录，不作为Git命令行密码输入。

## 安装软件后的检查点

当前应该做到：`py -3.12 --version`成功，`git --version`成功，知道自己的GitHub用户名。还没有课程文件、没有JupyterLab页面都是正常的，下面继续下载和安装课程环境。

## 3. 下载课程：第一次才clone

### 3.1 新同学，没有课程文件夹
打开一个普通PowerShell，先创建自己的课程父文件夹。以下命令可以原样复制；`$env:USERPROFILE`会自动替换成当前Windows用户目录，不需要改成姓名，也不需要D盘。

```powershell
New-Item -ItemType Directory -Path "$env:USERPROFILE\course-work" -Force
```

按回车，看到目录信息后，再输入：

```powershell
Set-Location "$env:USERPROFILE\course-work"
```

现在提示符末尾应是`course-work>`。这里只创建父文件夹，不要自己再建course-2026，下一条clone会自动创建。


输入下面命令，并等待下载结束：

```powershell
git clone https://github.com/prince19992516/-2026.git course-2026
```

然后进入下载好的课程目录：

```powershell
cd course-2026
```

确认位置：

```powershell
dir
```

**成功标志：** 能看到 `course.cmd`、`course.py`、`README.md`、`教材`、`教程`。这一层就是后文说的“仓库根目录”。不是 `教材` 子文件夹，也不是下载目录的上一层。

记住这个位置：`当前用户目录/course-work/course-2026`。以后打开PowerShell，可以直接输入下面一行回到课程根目录：

```powershell
Set-Location "$env:USERPROFILE\course-work\course-2026"
```

然后输入 `explorer .` 可打开当前文件夹的资源管理器窗口。若你使用了其他保存位置，请到自己的文件夹地址栏输入powershell，后文命令相同。

### 3.2 已经下载过课程文件夹
不要再往已有目录里面clone一份。在文件资源管理器打开已有文件夹，用地址栏启动PowerShell，先查看状态：

```powershell
git status
```

如果显示工作区干净（`working tree clean`），且当前分支是main，可更新：

```powershell
git pull --ff-only origin main
```

如果有未提交文件或正在自己的作业分支上，先按[提交教程](03-GitHub协作与提交.md)保存工作，再更新；不要使用reset或强推来“清空错误”。看不到 `course.cmd` 时，可能还没更新到新版，或当前目录不对。

用GitHub的Download ZIP也能获得文件并运行实验，但ZIP不含Git历史，不能直接按提交教程推送。需要提交作业的同学优先使用clone。

## 4. 自己创建虚拟环境并安装Python库

以下步骤在**课程根目录的PowerShell**中操作。输入`dir`能看到course.py、教材和教程，才继续。每个代码块是一条命令，回车后等它完成再输入下一条。

### 4.1 创建本课程专用的.venv

```powershell
py -3.12 -m venv .venv
```

含义：用Python 3.12的venv工具，在当前目录创建名为`.venv`的虚拟环境。通常没有很多输出；等提示符重新出现，再输入：

```powershell
.\.venv\Scripts\python.exe --version
```

看到Python 3.12.x表示这个环境里的Python可用。`.venv`是你在本机创建的，不是从仓库下载的，不上传GitHub，也不能复制同学的环境来代替自己安装。

已经有可用的.venv时，不必重建。若版本不对或环境损坏，先看第10节的修复方法，不要在旧目录中反复叠加安装。

### 4.2 安装运行Notebook和生成教材需要的库

把下面**整条命令**复制到PowerShell，按回车。页面自动折行不代表多条命令：

```powershell
.\.venv\Scripts\python.exe -m pip install numpy==1.26.4 scipy==1.14.1 matplotlib==3.9.2 pandas==2.2.3 sympy==1.13.3 jupyterlab==4.3.5 ipykernel==6.29.5 nbformat==5.10.4 nbclient==0.10.2 jupyter-book==1.0.4.post1 sphinx==7.4.7
```

前半段指定刚创建的Python；`-m pip install`表示用它安装库；`==`后是本课程使用的版本。请先按这套版本安装，以便组间复现。

| 库 | 用途 |
| --- | --- |
| numpy、scipy | 数组、线性代数和科学计算 |
| matplotlib | 绘图 |
| pandas、sympy | 数据整理和符号计算 |
| jupyterlab、ipykernel | Notebook编辑界面和执行代码的内核 |
| nbformat、nbclient | Notebook文件和Jupyter相关基础依赖 |
| jupyter-book、sphinx | 后面生成HTML教材时使用 |

安装时会显示Collecting、Downloading、Installing等英文日志，可能持续数分钟。**看到Successfully installed，或相应库已满足要求（Requirement already satisfied），且没有ERROR，随后提示符回来，再继续。** 安装期间不用打开浏览器，也不输入下一条命令。网络中断后，恢复网络并重新运行这一条安装命令即可。

### 4.3 注册Notebook内核

继续在同一终端输入：

```powershell
.\.venv\Scripts\python.exe -m ipykernel install --sys-prefix --name python3 --display-name "Python 3 (course-2026)"
```

这一步把刚安装的Python登记为Jupyter内核。看到`Installed kernelspec python3 in ...`后完成，路径应位于当前课程`.venv`中。`--sys-prefix`把登记信息放进这个环境；界面中显示的名称是“Python 3 (course-2026)”。

本教程直接写出`.venv`里的Python路径，**无需另外运行Activate.ps1**；以后新开终端也用这条路径，就能确定使用的是本课程环境。[Python虚拟环境说明](https://docs.python.org/3.12/library/venv.html)、[内核安装说明](https://ipython.readthedocs.io/en/stable/install/kernel_install.html)。

安装完成后继续下一节，打开并亲自运行实验。课程助手只用来启动Jupyter或生成、预览教材，不负责安装环境。

## 5. 窗口A：打开并使用JupyterLab

环境安装完毕后，现在运行下面这一条命令：

```powershell
.\course.cmd lab
```

**从这一步起，窗口A被持续占用是正常的。保持窗口A打开。Git或生成教材的命令应在新开的窗口B中输入。**

也可以在课程根目录双击`course.cmd`，输入`1`并回车启动，输入`0`退出菜单。

浏览器通常会自动打开JupyterLab。若没有弹出，找终端输出中带 `/lab?token=...` 的 `http://127.0.0.1:...` 或 `http://localhost:...` 链接，完整复制到浏览器地址栏。token是本机服务访问凭证，不要发到公开仓库；不要将链接中的文字逐段改写。

### 5.1 打开第一章
1. 在JupyterLab左侧文件列表双击 `教材`。
2. 双击 `第01章-误差的代价`。
3. 双击 `A组-实验.ipynb`。不要创建一个空文件来代替它。
4. 如果询问内核，选择 **Python 3 (course-2026)**。已有Notebook可通过 **Kernel → Change Kernel** 选择课程内核。
5. 点击 **Kernel → Restart Kernel and Run All Cells**，确认重启并运行。

不同语言界面的菜单文字可能翻译为“内核”“重启内核并运行所有单元”。运行时单元左侧可能显示 `[*]`，完成后变为数字 `[1]` 等。第一章应输出 `naive` 为0、`stable` 和 `reference` 约为 `5e-9`，且没有红色Traceback。

### 5.2 如何写文字、公式和代码
点击工具栏“+”增加单元；通过工具栏下拉框选择 **Markdown** 或 **Code**。

Markdown单元输入：

```markdown
## 我对本实验的解释
绝对误差为 $|\hat{x}-x|$。
```

Code单元输入（以下是Python代码，才放进Notebook）：

```python
import sys
print(sys.executable)
```

选中单元按 `Shift+Enter` 运行。输出的Python路径应属于课程 `.venv`。按 `Ctrl+S` 保存。这里保存的是本机文件，**并没有上传到GitHub**；上传操作见提交教程。

不要把 `git pull`、`.\course.cmd build`、`python -m jupyterlab` 等终端命令放进普通Code单元，也不要把Markdown标题当作Python程序运行。

## 6. 需要提交或生成教材时，再开窗口B

日常写文字和运行代码都在浏览器里的Notebook完成。启动Jupyter的终端持续显示日志，是正常现象。

| 位置 | 做什么 | 操作结束后怎样处理 |
| --- | --- | --- |
| 窗口A：启动Jupyter的PowerShell | 为浏览器提供JupyterLab服务 | 写作期间保持打开 |
| 浏览器里的Notebook | 写作、重启内核、运行、核对输出和保存 | 保存后可以继续编辑或关闭标签 |
| 窗口B：另开的PowerShell | Git提交，或按需生成和预览教材 | 普通命令完成后回到提示符 |

需要Git提交或生成教材时：先在浏览器按Ctrl+S保存；按Win+E打开课程根目录；点击地址栏输入`powershell`并回车。这是新的窗口B，不用重新启动Jupyter。接着按照[提交教程](03-GitHub协作与提交.md)或[生成教材教程](05-生成与查看教材.md)操作。

只有一个终端时，也可以先保存Notebook，在窗口A按Ctrl+C停止Jupyter，等提示符重新出现再输入其他命令。停止后浏览器会断开；下次重新运行lab即可。

## 7. 关闭服务与第二天重新打开

当天结束时先在Jupyter保存文件，再回到窗口A按 `Ctrl+C`。若出现是否关闭的询问，输入 `y` 并回车；按提示确认，直到出现命令提示符或回到课程助手菜单。关闭浏览器标签页不会自动关闭服务。

第二天不需要重新安装。进入课程文件夹，打开窗口A，运行：

```powershell
.\course.cmd lab
```

需要Git提交或生成教材时，再开窗口B。只有新电脑、环境损坏或依赖变化时才按第4节重新准备环境；普通文字修改不需要重装依赖。

## 8. 构建HTML教材（按需，不是每次写作必做）

在空闲的窗口B运行：

```powershell
.\course.cmd build
```

等待“构建完成”并返回提示符，再运行：

```powershell
.\course.cmd preview
```

浏览器打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)。preview现在持续占用窗口B，按 `Ctrl+C` 结束预览；它与Jupyter的8888端口是两个不同服务。完整的生成与查看步骤见[教材生成教程](05-生成与查看教材.md)。

## 9. macOS / Linux完整对应流程

### 9.1 Mac：先安装Python和Git

1. 用Safari打开[Python 3.12.10发布页](https://www.python.org/downloads/release/python-31210/)，在Files中选择 **macOS 64-bit universal2 installer**。这是图形安装器示例，并非最新补丁；已可用的3.12.x无需重装。
2. 等`.pkg`下载完成，打开Finder（访达）→ 下载，双击安装包；按“继续 → 同意 → 安装”完成系统要求的验证。官方说明见[在Mac上使用Python](https://docs.python.org/3.12/using/mac.html)。
3. 按 `Command+空格`，输入“终端”或“Terminal”，回车打开。以下每个代码块逐条执行，每条回车并等待结束。
4. 输入下面命令安装Apple命令行工具（包含Git）：

```bash
xcode-select --install
```

5. 如果弹出系统安装窗口，选择安装，按提示同意并等待完成；已经安装时会提示工具已存在，继续验证即可。若学校设备限制安装，请管理员协助。
6. 关闭并重新打开终端，执行下方Python和Git验证。后续若pip报证书错误，打开“应用程序 → Python 3.12”，运行安装器附带的`Install Certificates.command`，完成后重试pip安装命令；不要关闭证书校验。

### 9.2 Ubuntu 24.04：先安装Python和Git

本段仅针对Ubuntu 24.04。按 `Ctrl+Alt+T` 打开终端，输入 `cat /etc/os-release` 确认系统版本。其他Linux版本请助教给对应命令，不直接照搬apt步骤。

先更新软件包信息：

```bash
sudo apt update
```

要求密码时输入当前系统用户密码并回车，屏幕通常不显示星号或字符，这是正常的。等待结束，再安装：

```bash
sudo apt install python3.12 python3.12-venv git
```

若询问是否继续，确认安装这些包后输入 `Y` 并回车，等待完成。没有sudo权限时请管理员安装；后面的虚拟环境安装和Jupyter使用普通用户运行。

### 9.3 Mac和Ubuntu：下载课程并运行

GitHub账号按第2.3节注册。以下步骤在新的终端中进行。

先验证：

```bash
python3.12 --version
```

```bash
git --version
```

两条验证命令应分别输出Python 3.12.x和git version…。先创建并进入课程父目录：

```bash
mkdir -p "$HOME/course-work"
```

```bash
cd "$HOME/course-work"
```

第一次下载：

```bash
git clone https://github.com/prince19992516/-2026.git course-2026
```

```bash
cd course-2026
```

自己创建虚拟环境：

```bash
python3.12 -m venv .venv
```

查看环境里的Python版本，应显示3.12.x：

```bash
.venv/bin/python --version
```

安装库（整条命令一次复制）：

```bash
.venv/bin/python -m pip install numpy==1.26.4 scipy==1.14.1 matplotlib==3.9.2 pandas==2.2.3 sympy==1.13.3 jupyterlab==4.3.5 ipykernel==6.29.5 nbformat==5.10.4 nbclient==0.10.2 jupyter-book==1.0.4.post1 sphinx==7.4.7
```

等安装完成、没有ERROR且提示符回来，再注册内核：

```bash
.venv/bin/python -m ipykernel install --sys-prefix --name python3 --display-name "Python 3 (course-2026)"
```

窗口A单独启动Jupyter：

```bash
python3.12 course.py lab
```

新开终端窗口B（Mac可用 `Command+N`，Ubuntu可再次按 `Ctrl+Alt+T`）。先回到同一个课程文件夹：

```bash
cd "$HOME/course-work/course-2026"
```

窗口B用于Git提交或生成教材。需要生成整本教材时，分别运行 `python3.12 course.py build`、等待完成后运行 `python3.12 course.py preview`。这些助手命令自动使用 `.venv/bin/python`，**无需在每个新终端source激活**。也可运行 `python3.12 course.py` 打开数字菜单。

## 10. 常见问题：看到什么、先做什么

| 现象 | 原因或判断 | 操作 |
| --- | --- | --- |
| 打开Jupyter后终端不能继续输命令 | 服务持续运行，正常 | 保留窗口A，另开窗口B；不要重装 |
| 找不到course.cmd / course.py | 目录不对或仓库尚未更新 | 在根目录用dir/ls确认文件，再检查版本 |
| py不是内部或外部命令 / 无法识别py | Launcher没装好或终端未刷新 | 关闭重开终端；重新运行Python安装器补装Launcher |
| No suitable Python runtime / 找不到3.12 | 没有对应版本 | 安装3.12，再验证 `py -3.12 --version` |
| `.venv`不是Python 3.12 | 使用了其他版本建环境 | 先保存并关闭所有课程服务；按下面修复步骤处理 |
| pip下载超时、连接失败 | 网络或代理问题 | 恢复网络后重新运行第4.2节的pip安装命令；联系学校网络支持，不随意关闭证书校验 |
| No module named某包 | 环境不完整或内核错误 | 按第4.2节补齐依赖、第4.3节登记内核，再启动并选择课程内核 |
| 激活脚本提示禁止执行 | 使用了Activate.ps1 | 助手不需要激活脚本，直接用 `course.cmd` |
| 出现 `>>>` 提示符 | 进入了Python交互解释器 | 输入 `exit()` 回车，返回PowerShell再输入命令 |
| Notebook报SyntaxError，内容是终端命令 | 输入位置错了 | 删除该命令单元，在终端窗口B运行 |
| Notebook一直是 `[*]` | 计算尚未完成或阻塞 | 等待；明显异常时Kernel → Interrupt，检查代码；必要时Restart |
| AssertionError | 实测与预期不符 | 看失败单元、输入和容差，交B/C分析；不要删断言凑通过 |
| 生成教材失败 | 文件路径、目录或排版配置有问题 | 找第一条具体错误，修复后重跑build |
| 浏览器无法连接 | 服务没开、已停止或地址/端口错 | 看窗口A实际输出，复制其链接；需要时重新lab |
| 端口占用 | 已有服务运行 | 优先使用原服务；或 `.\course.cmd lab --port 8890` / `.\course.cmd preview --port 8001` |
| token失效 | 使用了旧服务的地址 | 复制当前窗口的完整链接 |
| 保存后GitHub看不到 | 只保存到本机 | 按提交教程commit、push并提交PR |

macOS/Linux的端口命令对应 `python3.12 course.py lab --port 8890` 等。Jupyter端口被占用时也可能自动选择下一个端口，以实际日志为准。

**修复损坏环境：** 先保存Notebook并停止Jupyter和预览服务。在文件资源管理器把课程 `.venv` 文件夹改名为 `.venv-old`（若已有同名备份，选另一个名字），回到课程目录，重新执行第4.1—4.3节（Mac/Linux按第9.3节）。不要重命名或删除 `教材`。备份环境不能跟着作业上传，本仓库已忽略 `.venv-*`。

**向助教求助时提供：** 操作系统、运行的完整命令、当前目录、第一条具体报错及后面的Traceback、Python版本。先删去日志中的token和个人信息。不要只发“不能运行”。
