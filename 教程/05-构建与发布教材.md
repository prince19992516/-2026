# 05 构建、查看和发布整本教材

“构建”把Markdown正文和Notebook组合成HTML教材；“预览”启动一个本地网页服务供浏览器查看。两者是分开的步骤。默认交付HTML，课程源文件仍保留在GitHub。

## 1. 先准备空闲的终端窗口B
已按[安装教程](01-环境安装与运行.md)完成setup。保存Jupyter中所有相关文件；保留运行Jupyter的窗口A，在课程根目录另开PowerShell作为窗口B。不要在窗口A的日志里输入以下命令，也不要输入Notebook普通Code单元。

## 2. 检查：执行完会返回提示符

Windows窗口B输入：

```powershell
.\course.cmd check
```

macOS/Linux窗口B输入：

```bash
python3.12 course.py check
```

选自己系统的一条执行，不用两条都运行。等待完成，确认 `failed` 为0。placeholder表示学生尚未补充的验证Notebook，不表示章节已验收。

## 3. 构建：执行完会返回提示符

Windows：

```powershell
.\course.cmd build
```

macOS/Linux：

```bash
python3.12 course.py build
```

构建会重新执行目录中的实验。日志中看到 `Executing notebook` 是正常的；等待 `build succeeded` 和“构建完成”。输出文件夹是 `教材/_build/html/`，包含首页、各章节和样式文件。看到“本步未成功”时先修复第一条具体错误，不要继续preview旧文件当作新版成果。

## 4. 预览：这个命令会持续占用窗口B

Windows：

```powershell
.\course.cmd preview
```

macOS/Linux：

```bash
python3.12 course.py preview
```

保持窗口B打开，浏览器访问 [本地教材](http://127.0.0.1:8000)。这与JupyterLab的8888端口不同；127.0.0.1指自己的电脑，发给同学不能让他们访问你的教材。

结束预览时在窗口B按 `Ctrl+C`。修改内容后需先重新build，再preview或刷新浏览器；浏览器不会自动把源Notebook的修改变成新的教材。

## 5. 出错和重复使用
- 端口8000占用：先停止旧预览，或使用 `.\course.cmd preview --port 8001`（macOS/Linux使用对应Python助手），访问输出的新地址。
- 提示没有HTML：先build，确认成功且目录存在。
- 链接或图表缺失：检查 `_toc.yml`、相对路径和构建日志；不要只复制index.html。
- 预览结束想检查：按Ctrl+C返回提示符，再运行check。

日常写单章只需保存、运行和check；整书build通常用于助教验收或需要查看排版时。

## 6. GitHub Actions里下载现成教材
1. 打开课程仓库 → **Actions** → “教材检查与构建”。
2. 点击对应提交的运行记录，等待Windows、Linux和 `build-book` 都变绿。
3. 在该运行页面下方 **Artifacts** 找到 `textbook-html`，点击下载，解压到自己的文件夹。下载可能需要登录GitHub。
4. 用课程的Python启动下载文件夹的预览。下面是Windows示例，**在课程根目录窗口B中输入，并把路径改成实际解压目录**；那个目录内应直接存在index.html：

```powershell
.\.venv\Scripts\python.exe -m http.server 8000 --bind 127.0.0.1 --directory "C:\Users\你的用户名\Downloads\textbook-html"
```

然后浏览器打开127.0.0.1:8000；该命令也持续运行，Ctrl+C停止。macOS/Linux用 `.venv/bin/python` 替换Python路径，并替换成自己的下载目录。

若push后尚未出现运行记录，有权限的助教可以在工作流页面选择 **Run workflow → main → Run workflow** 手动触发。检查运行记录中的commit是否对应实际版本，不能拿旧版本绿灯当新版本结果。

同页的 `notebook-results-*` 包含执行后的Notebook和summary.json，供查看具体输出；这些日志不能替代B/C报告。

## 7. 教材目录与正式版本
`教材/_toc.yml` 决定全书顺序，默认包括前言、正文、实验和习题。报告与答案在仓库中供核查，未纳入学生版目录不代表保密。源Notebook不会被构建器覆盖。

正式发布前，由助教逐章验收、收齐三组报告、统一符号和引用。需要对外发布时，在GitHub Release说明中填写真实日期、完整commit、作者、依赖和局限，并附完整HTML压缩包；仓库不预建发布目录。当前只是脚手架，不能将占位文件记成已验收章节。

## 8. PDF和在线阅读
默认配置并验证的是HTML。整本中文PDF另需TeX、中文字体、XeLaTeX/ctex设置及排版检查；浏览器打印单章可以作为临时阅读方式，不能保证全书排版。

工作流上传HTML产物，不会自动开启GitHub Pages。若后续要让同学通过公共网址阅读，需要另行配置Pages发布来源。
