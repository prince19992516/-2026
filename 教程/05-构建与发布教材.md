# 05 构建与发布教材

## 本地生成整本HTML教材
激活主环境或使用其Python路径，在仓库根目录运行：

```bash
python 脚本/检查结构.py
python 脚本/验证AI陷阱.py
python 脚本/检查笔记本.py
python 脚本/构建教材.py
python -m http.server 8000 --directory 教材/_build/html
```

浏览器打开 [本地教材](http://localhost:8000)。构建过程使用Jupyter Book 1.x，强制重新执行目录中的实验；警告和执行失败都会使构建失败。编辑后再运行构建命令。

`教材/_toc.yml` 控制全书顺序，默认包括前言、每章正文、实验和习题；报告与答案保留在仓库供教师核查。源Notebook不被覆盖，构建目录已忽略。

## GitHub上获取教材
向main推送或提交PR后，在Actions中打开“教材检查与构建”。Windows/Linux Notebook检查均通过后，`build-book` 生成 `textbook-html` 产物。下载解压，运行本地HTTP服务器即可阅读；该产物是完整文件夹，不能只复制index.html。

还可下载 `notebook-results-*` 查看执行后Notebook和 `summary.json`。其中 `placeholder` 表示没有可执行代码的待完成文件；不计为通过。CI日志不是B/C科学验证报告。

## 正式版本
1. 按期末审阅表验收八章，收齐三组报告与修订证据。
2. 在 `发布/v1.0/发布说明.md` 填写真实commit、日期、作者、环境、已知问题与授权。
3. 保存最终依赖快照；在GitHub Releases创建版本并上传HTML压缩包和已审核的PDF等产物。
4. 只有内容完成并验收后才标记v1.0；脚手架阶段不能称为已出版教材。

## PDF与在线阅读
HTML是默认已配置构建目标。需要PDF时可先用浏览器打印单章；整本PDF另需安装适合中文的TeX发行版和字体、配置XeLaTeX/ctex并检查分页公式，**本脚手架不承诺开箱即得整本中文PDF**。

需要公共在线教材时，可后续配置GitHub Pages并选择发布来源；当前工作流只上传构建产物，不自动启用Pages或发布网站。
