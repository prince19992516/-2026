# 04 助教操作手册

## 开课前
1. 在章节分工表填写实际小组编号、A/B/C轮换任务、课程日期和参考资料；确认本仓库8章是否符合导师教学目标。
2. 在Settings中邀请必要的协作者；其余学生可通过Fork提交。给main设置PR审阅和状态检查规则（功能取决于仓库与账号支持情况）。
3. 运行首次Actions后，将 `notebook-ubuntu-latest`、`notebook-windows-latest`、`build-book` 作为所需检查；设置教师或助教负责最终合并。工作流文件本身不会自动开启分支保护。
4. 用第一章带学生完成一次“运行 → 提交 → 验证 → 人工复核 → 修订”演练，确认每人会打开Notebook和读取断言失败。
5. 公布[角色规则中的验收要求](../协作管理/三组协作规则.md)与评分规则；不要让学生误以为CI绿色即满分。

## 第一节实践课：逐个确认学生能独立完成
预先发送[从零安装教程](01-环境安装与运行.md)，用投屏演示软件安装和目录定位。课堂上依次检查：`.\course.cmd setup`完成 → doctor找到课程Python → 打开第一章 → 区分Markdown/Code → 运行并保存 → 保持窗口A、另开窗口B检查 → commit/push → 提交PR → 看懂Actions结果。

尤其让每位同学亲自完成“Jupyter仍开着时在另一个终端运行检查”，不要只演示启动。发给已卡住学生的短教程是[已打开JupyterLab怎么办](00-已经打开JupyterLab接下来怎么办.md)。macOS/Linux用安装教程中的对应助手命令；Conda、Docker和GPU不作为首课必做任务。

课程助手会明确提示持续运行的服务和会返回的命令；`lab`与`preview`需要保持终端，其他操作完成后会返回。辅助程序和教程调整时，CI也要验证同一条学生安装路线，而不是只测助教电脑已有环境。

## 每章管理
**每个实际小组至少参与3个不同章节，分别完成过A、B、C角色。** 开始前检查分配是否满足要求，结束时按真实报告和贡献核对；同章的三个角色由不同小组承担。示例与汇总见[章节分工表](../协作管理/章节分工表.md)。

用任务Issue给出学习目标、先修内容、A/B/C负责人、各阶段截止日期和验收标准。按[三组规则](../协作管理/三组协作规则.md)执行闭环；每次审阅指向明确版本，记录未解决问题。

## 如何给研究生编辑权限
公开仓库允许别人查看、下载和Fork，不等于允许任何人直接推送到课程仓库。没有写权限的人可以从Fork提交PR，请教学团队审阅后接纳。

1. 收集研究生的GitHub用户名。
2. 用仓库所有者账号打开仓库，进入 **Settings → Collaborators → Add people**。
3. 搜索并确认账号，点击邀请。
4. 对方接受邀请后获得协作者权限，可以推送修改。应继续按课程流程建立分支、提交PR。

协作者权限针对仓库，A/B/C负责文件的约定不等于目录访问隔离。不要仅靠分组说明来限制学生只能修改某个目录。应为main另行设置审阅和自动检查规则；如需指定教师批准，可结合CODEOWNERS与相应的必需审阅设置。

参考：[GitHub邀请协作者说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/inviting-collaborators-to-a-personal-repository)、[个人仓库权限说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/permission-levels-for-a-personal-account-repository)。本教程不会自动发送邀请或开启分支保护。

## 进度跟踪
直接更新章节分工表与任务/PR状态，检查角色报告、具体贡献和跨组阻塞。协调B独立复现与C风险核验时间，并核对每组尚缺的章节与角色；不另外提交周报或会议记录。

## 建议评分维度（由导师确认后实施）

| 维度 | 建议权重 | 主要证据 |
| --- | --- | --- |
| 本组职责完成质量 | 40% | A内容与习题；B测试；C风险核验、反例与方法对比 |
| 正确性、复现与证据 | 30% | 实验、独立参考、边界与反例 |
| 报告清晰度与来源 | 15% | 版本、引用、方法、局限 |
| 协作与修订闭环 | 15% | PR、问题回应、复测、个人贡献 |

这是一套建议，不是已获导师批准的正式课程评分标准。人工工作应结合现场解释、推导或口头答辩核查，不能仅靠文件声明确认。

## 期中、期末与出版
阶段性评价使用 `阶段性评价/期中/` 和 `阶段性评价/期末/`，当前仅保留空目录占位，不预填报告或任务。教师布置具体评价后再添加材料。期中检查角色轮换和未决问题；期末核对每组至少完成3个不同章节且A/B/C齐全，再逐章验收并统一符号、引用和难度。正式教材版本仅在真实验收后生成。
