# 07 目录和.gitkeep是什么

## 第一次打开仓库，先看哪些文件

| 文件或目录 | 用途 | 学生需要做什么 |
| --- | --- | --- |
| README.md | 首页和教程入口，.md表示Markdown文字文件 | 先阅读 |
| course.cmd | Windows课程助手，.cmd是可运行的命令文件 | 按教程准备好.venv和依赖后双击，或在PowerShell运行 |
| course.py | 同一助手的Python程序 | macOS/Linux按教程调用；日常不用改代码 |
| 教材/第xx章…/README.md | 本章内容、角色分工与文件清单 | 先查本次组名和任务 |
| 教材/第xx章…/模板/ | 本章所有原始模板及模板图片 | 复制自己角色需要的文件，保留原件 |
| 教材/第xx章…/工作/ | 本章所有小组稿、报告、AI记录及整合稿 | 编辑自己的副本，不改别组文件 |
| 教材/第xx章…/工作/图片/ | 小组实际使用的图片 | 上传或复制图片，文件名带本章组别 |
| 协作管理/ | 各章组别、阶段截止日期与角色规则 | 查看G1—G22组别、截止日期及本章角色 |
| 教程/ | 安装、运行、提交和构建教程 | 按当前步骤阅读 |
| .github/ | GitHub任务、问题和PR文字模板 | 提交时按实际工作填写 |
| .gitignore | 避免把.venv、缓存等本机文件提交到GitHub | 保留即可，普通写作不用修改 |
| .gitattributes | 统一不同系统的文本换行，保证Windows命令文件的格式 | 保留即可，普通写作不用修改 |
| 阶段性评价/期中/、阶段性评价/期末/ | 教师后续安排评价材料的位置 | 当前留空，等具体要求 |
| .venv/ | 按安装教程在本机亲手创建的Python环境 | 不上传，不从别的电脑复制 |
| 教材/_build/ | 生成的HTML教材 | 可以查看，不当作学生源文件提交 |
| 教材/_ext/local_images.py | 生成网页时处理中文图片路径 | 随build自动调用，学生不用运行或修改 |

## course.cmd、course.py和_ext要不要操作

这三个文件仍有用途，需要保留。正确文件名是`course.py`。

- **course.cmd**：Windows入口。完成[环境安装](01-环境安装与运行.md)后，双击可打开菜单；在课程根目录的PowerShell输入`.\course.cmd lab`启动JupyterLab，输入`.\course.cmd build`生成HTML教材，输入`.\course.cmd preview`预览已生成的教材。每次选需要的一项运行即可。
- **course.py**：上面菜单与命令的实际Python程序，course.cmd会调用它。macOS/Linux按教程用`.venv/bin/python course.py lab`等命令调用。两者不自动安装环境，也不检查数学结论；日常写作不需要修改它们。
- **教材/_ext/local_images.py**：生成网页时使用的小扩展，处理中文图片路径，避免网页生成时找不到插图。它由教材配置自动加载，不需要双击、手动运行或填写内容；删除它会影响教材生成。

`lab`和`preview`运行期间会占用各自的终端，这是正常现象。窗口保持打开；需要执行其他命令时另开一个终端并进入课程根目录。停止服务时回到对应终端按Ctrl+C；Jupyter若询问是否关闭，输入y并回车。详细步骤见[生成与查看教材](04-生成与查看教材.md)。

## .gitkeep是空目录的占位文件

Git保存文件的版本，不能只保存一个真正的空文件夹。为了让同学下载后仍看到每章的 `工作/`、`工作/图片/`，以及“期中”“期末”目录，这些位置留下**内容为空的 `.gitkeep` 文件**。这是常用的占位名称，没有特殊执行功能。

```text
教材/第01章-误差的代价/       其余七章采用相同结构
├─ README.md                 本章入口
├─ 模板/                     原件保留在这里
│  ├─ 模板-A组-正文.md
│  ├─ 模板-A组-实验.ipynb
│  ├─ ……                     其余A/B/C模板
│  └─ 图片/                  模板图片或绘图说明
└─ 工作/                     本组副本、报告、整合稿放这里
   └─ 图片/                  实际使用的图片放这里
      └─ .gitkeep

阶段性评价/
├─ 期中/
│  └─ .gitkeep
└─ 期末/
   └─ .gitkeep
```

`工作/` 最初只放占位文件和图片文件夹，还没有小组成果；模板里的导入图也没有自动复制到 `工作/图片/`。阶段性评价的两个目录仍没有预填材料。**`.gitkeep` 不用打开、不用填写、不用运行，留着即可，也不参与评分。**

本仓库只在空目录保留 `.gitkeep`。目录里已经有正文、图片或其他已保存文件后，删除这个目录里的 `.gitkeep`；子目录仍为空时，保留子目录自己的占位。网页版删除：先上传实际文件，再在自己的任务分支打开 `.gitkeep`，点右上角“…”菜单的Delete file并提交，随同一PR交上来。但**空目录若删掉唯一的.gitkeep，下次clone时就不会出现该目录**。不要删`.git`目录（本地版本历史）或把`.gitignore`当占位文件（它用于排除环境和缓存）。

Windows若隐藏扩展名：文件资源管理器中，Windows 11选择“查看 → 显示 → 文件扩展名”，Windows 10在“查看”页勾选“文件扩展名”。这有助于区分`.md`文字、`.ipynb`Notebook和`.cmd`课程助手。

## 模板与小组文件名怎么看

本章 `模板/模板-A组-正文.md` 是原件；A1、A2各自复制到同章 `工作/`，正文按“角色-G编号-正文”命名，例如第01章分别为 `A1-G20-正文.md`、`A2-G22-正文.md`，各自填写全章四节，形成两份独立完整稿。B/C同理，例如 `B2组-验证报告.md`、`C1组-AI陷阱.md`。组号按本章分工表顺序确定，G编号仍是实际小组身份；同一G组换章后角色前缀会变化。

每组的AI对话单独存放，如 `A1组-AI对话记录.md` 与 `A2组-AI对话记录.md`。这些文件都放在本章 `工作/`。图片放在 `工作/图片/`，新增图片文件名带本章组名；从工作里的正文引用时写 `图片/实际文件名`。整合稿也放在 `工作/`，使用 `整合-*` 前缀。完整复制、改名和修改链接步骤见[模板使用说明](02-Notebook教材写作.md#模板复制与命名)。
