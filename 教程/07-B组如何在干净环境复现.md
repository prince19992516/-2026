# 07 B组如何在干净环境复现A组实验

本教程中的B组指本章承担B角色的实际学生小组；换章后可承担A或C。每组至少参与3个不同章节并分别完成过A/B/C，本章不能验证自己此前编写的内容。

“独立运行”包含两件事：在干净内核中顺序运行，以及在新建环境中验证依赖是否完整。只点击Restart Kernel完成了前者；本教程用新的课程副本和 `.venv` 完成后者，不要求初学者安装Docker。

先完成[基础安装教程](01-环境安装与运行.md)。以下以Windows第一章为例；在新的空闲PowerShell中操作，原来的Jupyter窗口可以保留，先保存有关文件。

## 1. 先保存独立推导，再打开A的实现
根据助教给出的题目、假设和参考资料，在自己的工作副本填写 `B组-独立推导.md`：先记录人工初始推导与预期，再记录另一AI的补充。保存commit或时间证据，之后才查看A组实现。若提前看过，披露看过的范围，不伪造“盲审”。

## 2. 得到被审版本
让A组提供已推送到GitHub的完整commit SHA。它确定的是某一版内容；不要只写“最新版”。尚未推送的本地commit，B组不能从远程克隆得到。

## 3. 在父目录建立新的复现副本
通过文件资源管理器打开原课程文件夹的**上一层**，地址栏输入powershell回车。运行：

```powershell
git clone https://github.com/prince19992516/-2026.git course-review-ch01
```

等待结束再输入：

```powershell
cd course-review-ch01
```

这个目录名字只是第一章示例；如果已经存在，选择新的名字，例如course-review-ch01-round2，不覆盖旧复现证据。

切换到固定内容版本，下行的占位词必须替换成A提供的实际SHA：

```powershell
git switch --detach 完整commitSHA
```

核对当前版本：

```powershell
git rev-parse HEAD
```

输出必须等于被审SHA。`detached HEAD`表示当前固定在一个历史版本上，用于只读复现是正常的；不要在这里直接写要提交的正式报告。若Git找不到某个PR的commit，请助教协助获取对应远程分支/PR，不要悄悄改成main代替该版本。

## 4. 自己安装新环境

新克隆的目录不包含别人的`.venv`。在**新的复现副本根目录**重新执行[环境安装教程](01-环境安装与运行.md)第4.1—4.3节：创建.venv、用pip安装指定库、登记内核。Mac/Linux对应第9.3节。

依赖版本以被审内容版本的安装教程为准，必要时记录教师约定的修订版本。不要先复制A的环境，或安装A电脑上其他未登记的库来“补到能跑”，否则会漏掉依赖缺失问题。

如果A的扩展实验声明了额外依赖，按其说明自行安装并记录；若未说明必需依赖，应作为复现问题反馈。

## 5. 亲自运行并保留证据

在这个复现副本的终端启动JupyterLab：

```powershell
.\course.cmd lab --port 8890
```

使用不同端口便于与原工作副本区分，以终端实际输出的地址为准。依次完成：

1. 在新打开的JupyterLab左侧双击`教材`，再双击`第01章-误差的代价`和`A组-实验.ipynb`。
2. 选择该副本的课程内核，在一个临时代码单元运行`import sys; print(sys.executable)`，确认Python路径位于`course-review-ch01/.venv/`。记录后可删除这个临时单元。
3. 点击 **Kernel → Restart Kernel and Run All Cells**，等待全部执行结束。
4. 逐项比较自己的独立预期、A的说明和实际输出，记录容差、差异、报错以及尚未运行的部分。
5. 按Ctrl+S保存该副本中的实际运行结果，作为本地复现证据；不要在这个固定历史版本的副本中直接提交正式报告。

把当前SHA、Python版本、设备、种子和实际输出记录到验证报告。需要保存依赖版本时，在此复现目录另开终端运行：

```powershell
.\.venv\Scripts\python.exe -m pip freeze > 本机依赖快照.txt
```

结束时先保存Notebook，再到这个副本的Jupyter终端按Ctrl+C停止服务。不要把原工作目录的输出误记成新环境的结果。

## 6. 回到自己的工作分支写报告
在原来的工作副本/分支中填写 `B组-验证报告.md`、`B组-验证.ipynb` 和 `B组-修正清单.md`，记录被审A组SHA及复现目录/环境。将必要的精简输出和证据纳入报告；不要上传整个 `.venv` 或把构建缓存当作报告。

复现失败也是有效结果：写明第一处错误、最小复现步骤及影响。A修复后，对新的内容SHA重复独立复测；涉及依赖变更时使用新的环境/副本，不覆盖原来的失败记录。

## macOS / Linux对应操作
同样新建克隆并固定SHA，按安装教程第9.3节亲手建立环境、安装库和登记内核，然后运行 `python3.12 course.py lab --port 8890`，在浏览器亲自运行、核对并保存。保存依赖用 `.venv/bin/python -m pip freeze`；运行这条命令时另开终端进入复现目录。

新的虚拟环境能查出很多依赖和隐藏状态问题，但不是全新操作系统。若实验依赖系统库、GPU或外部求解器，应记录这些条件，必要时由助教安排容器或第二台设备复现。
