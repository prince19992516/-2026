# 08 目录和.gitkeep是什么

## 第一次打开仓库，先看哪些文件

| 文件或目录 | 用途 | 学生需要做什么 |
| --- | --- | --- |
| README.md | 首页和教程入口，.md表示Markdown文字文件 | 先阅读 |
| course.cmd | Windows课程助手，.cmd是可运行的命令文件 | 安装Python后双击，或在PowerShell按教程运行 |
| course.py | 同一助手的Python程序 | macOS/Linux按教程调用；日常不用改代码 |
| 教材/第xx章…/ | 正文、实验、习题与本章角色报告 | 修改分配给自己的章节和角色文件 |
| 模板/ | 新内容需要时复制的格式示例 | 各章已有模板，无需全部再交一遍 |
| 协作管理/ | 角色规则、章节分工与完成汇总 | 查本章角色；A/B/C会轮换 |
| 教程/ | 安装、运行、提交和构建教程 | 按当前步骤阅读 |
| 环境/、脚本/、.github/ | 依赖配置、自动检查与GitHub工作流 | 按教程运行，普通写作不用修改 |
| 阶段性评价/期中/、阶段性评价/期末/ | 教师后续安排评价材料的位置 | 当前留空，等具体要求 |
| .venv/ | setup自动生成的本机Python环境 | 不上传，不从别的电脑复制 |
| _build/、教材/_build/ | 检查或构建自动生成的结果 | 可以查看，不当作学生源文件提交 |

## .gitkeep是空目录的占位文件

Git保存文件的版本，不能只保存一个真正的空文件夹。为了让同学下载后仍看到“期中”“期末”这两个目录，每个目录留下一个**内容为空的.gitkeep文件**。这是常用的占位名称，没有特殊执行功能。

```text
阶段性评价/
├─ 期中/
│  └─ .gitkeep
└─ 期末/
   └─ .gitkeep
```

这里没有预填的报告、评价表或作业内容。`.gitkeep`不是报告，不用填写、不用运行，不参与评分。各章尚无图片的图片目录也用它占位；已有实际文件的普通目录不需要额外占位。

日常可以直接忽略它。以后放入真正的评价材料或图片后，可以删除那个目录的.gitkeep，也可以暂时保留；但**空目录若删掉唯一的.gitkeep，下次clone时就不会出现该目录**。不要删`.git`目录（本地版本历史）或把`.gitignore`当占位文件（它用于排除环境和缓存）。

Windows若隐藏扩展名：文件资源管理器中，Windows 11选择“查看 → 显示 → 文件扩展名”，Windows 10在“查看”页勾选“文件扩展名”。这有助于区分`.md`文字、`.ipynb`Notebook和`.cmd`课程助手。

## A/B/C文件名为什么保留

文件名表示本章角色职责。例如G01第01章当A，写编写报告；第02章当B，写验证报告；第03章当C，写批判报告与AI陷阱。每组至少参与3个不同章节并分别完成A/B/C。分工表和报告中的实际小组编号才说明是谁完成的，无需把文件名改成固定小组名字。
