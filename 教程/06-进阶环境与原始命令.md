# 06 进阶环境与原始命令（选读）

先完成[入门教程](01-环境安装与运行.md)。本文供已经理解环境、内核与终端的同学选择替代方案；不是要求所有学生都安装这些工具。

## 课程助手到底做了什么
`course.cmd` 在Windows定位本课程目录，然后用现有 `.venv` 的Python运行 `course.py`；首次没有 `.venv` 时用 `py -3.12` 启动。`course.py` 无论从哪里调用都以自身所在的仓库为根目录，执行动作时固定使用该仓库 `.venv`。

| 助手命令 | 对应动作 | 是否占用当前终端直到手动关闭 |
| --- | --- | --- |
| setup | 创建环境、pip安装、注册内核、doctor | 否，成功/失败后返回 |
| doctor | 查版本、导入、内核和pip依赖 | 否 |
| lab | 启动JupyterLab服务 | 是 |
| check | 结构、陷阱格式、Notebook执行 | 否 |
| build | Jupyter Book强制重新构建 | 否 |
| preview | 在127.0.0.1上提供HTML | 是 |

Windows以下原始命令全部在课程根目录的**空闲PowerShell**输入，按顺序逐条执行，失败先处理。无需执行Activate.ps1：

```powershell
py -3.12 -m venv .venv
```

```powershell
.\.venv\Scripts\python.exe -m pip install -r 环境/requirements.txt
```

```powershell
.\.venv\Scripts\python.exe -m ipykernel install --sys-prefix --name python3 --display-name "Python 3 (course-2026)"
```

安装后，**窗口A仅运行这一条并保持打开**：

```powershell
.\.venv\Scripts\python.exe -m jupyterlab
```

**另开窗口B，进入相同课程根目录**，按需逐条执行。每步结束并返回提示符后才输入下一步：

```powershell
.\.venv\Scripts\python.exe 脚本/检查结构.py
```

```powershell
.\.venv\Scripts\python.exe 脚本/验证AI陷阱.py
```

```powershell
.\.venv\Scripts\python.exe 脚本/检查笔记本.py
```

```powershell
.\.venv\Scripts\python.exe 脚本/构建教材.py
```

macOS/Linux先用 `python3.12 -m venv .venv`，后续将 `.\.venv\Scripts\python.exe` 换成 `.venv/bin/python`。若选择手动激活，**每新开一个终端都要重新激活**；入门助手避免了这一步。

## Conda：替代venv，不与助手环境混用
已安装Conda且清楚环境管理的同学可以用本节。助手固定查找 `.venv`，不会自动切换到Conda；因此本节用激活后的 `python` 执行原始命令。

首次在支持conda的终端（Windows可用Anaconda Prompt）进入课程根目录，然后进入环境目录：

```text
cd 环境
```

```text
conda env create -f environment.yml
```

创建结束后：

```text
conda activate scientific-computing-2026
```

```text
cd ..
```

```text
python -m ipykernel install --sys-prefix --name python3 --display-name "Python 3 (course-2026)"
```

窗口A运行 `python -m jupyterlab` 并保留。**新开的窗口B必须重新执行conda activate，cd到课程根目录**，然后逐条执行 `python 脚本/检查结构.py`、`python 脚本/验证AI陷阱.py`、`python 脚本/检查笔记本.py`。它们是三条独立命令，不要连写一行。需要构建时另执行 `python 脚本/构建教材.py`。

每日只需激活已有环境；不要重复conda env create。用 `python -c "import sys; print(sys.executable)"` 确认当前Python属于上述Conda环境。

## Docker：助教或熟悉容器的同学使用
安装并启动Docker Desktop的Linux容器模式（或Linux Docker Engine）。仓库根目录构建镜像：

```bash
docker build -f 环境/Dockerfile -t course-2026 .
```

等待构建成功，窗口A再启动容器（PowerShell或常见POSIX shell）：

```bash
docker run --rm --name course-2026-lab -p 127.0.0.1:8888:8888 -v "${PWD}:/course" course-2026
```

保持窗口A打开，复制日志里的本地token链接到浏览器。挂载让教材编辑保存在宿主目录；容器中使用镜像Python，不使用宿主Windows `.venv`，不要在容器内运行课程助手。

窗口B逐条检查，每条完成再下一条：

```bash
docker exec course-2026-lab python 脚本/检查结构.py
```

```bash
docker exec course-2026-lab python 脚本/验证AI陷阱.py
```

```bash
docker exec course-2026-lab python 脚本/检查笔记本.py
```

结束前保存Notebook，然后在窗口B运行 `docker stop course-2026-lab`。`--rm`删除容器实例；教材因挂载保存在宿主目录。依赖变更后需要重建镜像。Conda与Docker在不同设备上的安装仍需各自验证，本仓库默认CI检查CPU Python环境。

## 可选AI依赖与GPU
第6章扩展训练时才需要可选依赖。默认实验无需GPU或API密钥。先完成基础环境，再在空闲窗口B运行（Windows）：

```powershell
.\.venv\Scripts\python.exe -m pip install -r 环境/requirements-ai.txt
```

```powershell
.\.venv\Scripts\python.exe -m pip check
```

macOS/Linux用 `.venv/bin/python`。可选依赖可能下载数百MB或更多，耗时更长；发生错误先停止，不要用修改核心依赖版本的方式绕过。安装后重启Notebook内核。此可选组合已做Windows依赖解析，实际训练、GPU和其他平台仍需单独验证。

GPU配置取决于设备、驱动和框架，按 [PyTorch官方安装](https://pytorch.org/get-started/locally/) 或 [JAX安装说明](https://docs.jax.dev/en/latest/installation.html) 选择；不要把某台电脑的CUDA命令视为所有学生通用命令。需要不同依赖组合时建立独立实验环境并记录复现方式。

## 版本记录
主环境固定直接依赖，间接依赖可能随时间变化。正式验收保存实际Python、操作系统和pip freeze输出。Windows可在课程根目录运行下面一条生成本地记录；文件中如有本地路径或敏感来源，提交前先检查：

```powershell
.\.venv\Scripts\python.exe -m pip freeze > 环境/本机依赖快照.txt
```

不要单独把Jupyter Book升级到2.x再沿用本仓库1.x配置。依赖调整需先在干净环境复现，再更新教程和CI。
