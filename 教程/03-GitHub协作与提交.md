# 03 网页版提交：登录 GitHub → Add file → 提交 PR

本课程日常提交使用 **GitHub 网页**。先按[01](01-环境安装与运行.md)安装并在本机写好文件，再按本页上传；上传不需要在终端运行 `git add`、`git commit` 或 `git push`，也不用停止 JupyterLab。用 Download ZIP 下载的文件也可以按本页上传。

## 1. 先认清四件事

| 动作 | 文件在哪里 | 助教能在 main 看见吗 |
| --- | --- | --- |
| 在 JupyterLab 按 Ctrl+S | 你电脑上 | 不能 |
| 网页 Add file → Upload files → Commit changes | 网页当前选中的分支 | 上传到任务分支时，main 还没有 |
| Create pull request，简称 PR | 提出把任务分支合入 main 的申请 | 可以在 PR 查看，仍待合并 |
| PR 显示紫色 Merged | 已合入 PR 的目标分支 | 目标为课程 main 时，可以 |

**分支不是文件夹。** 浏览器左上角的分支选择框决定这次上传到哪里。网页切换分支不会替你切换或保存电脑里的文件。网页 main 是最终教材；自己的任务分支用来交稿。

## 2. 第一次：登录并确认权限

1. 浏览器打开[课程仓库](https://github.com/prince19992516/-2026)，登录自己的 GitHub 账号。右上角应出现头像。
2. 如果助教邀请你成为协作者，先到邮件或 GitHub 通知里 **Accept invitation（接受邀请）**。只注册账号不等于接受了邀请。
3. 有课程仓库写权限：在课程仓库操作，走下面的普通路线。
4. 没有写权限：使用本页第8节的 **Fork 路线**。公开仓库可以查看、下载，但不意味着任何人都能直接修改 main。

## 3. 核对组别，准备文件

到本章 README 看自己的 G 编号及 A1/A2、B1/B2、C1/C2 身份。**A1 和 A2 各自写完整一章，不是分成上下半章。** 允许使用 AI，仍需检查公式、实际运行代码并如实记录。

正文统一命名为 `本章角色-G编号-正文.扩展名`，例如：

| 小组任务 | 正文文件名 |
| --- | --- |
| 第01章 A1，G20 | `A1-G20-正文.md` |
| 第01章 A2，G22 | `A2-G22-正文.md` |
| 第02章 A1，G8 | `A1-G8-正文.md` |
| 第02章 A2，G21 | `A2-G21-正文.md` |
| 第07章 A1，G1，使用 Notebook 写正文 | `A1-G1-正文.ipynb` |

每组只保留一份正文；多个人分写的小节先按本章节号合在这一份里。已有稿就继续改已有文件，不再交“正文(1)”“最终版2”。正文以外的实验、习题、报告、AI记录仍用现有组别文件名，不必跟着全部改名。

在 JupyterLab 保存。Notebook 如需上交输出，先运行相关单元再保存。按 Win+E 打开文件资源管理器，找到电脑上 `教材/你的章节/工作/`。确认扩展名是 `.md` 或 `.ipynb`，不是 `.txt`、网页 `.html` 或快捷方式。

**这次只选择自己实际修改的文件和引用的图片。** 不上传 `.venv`、`.git`、缓存、整个课程目录、含姓名的分组 Excel、账号密码。公开文件只写组别。模板原件留在 `模板/`，提交自己的副本到 `工作/`。

## 4. 在网页选择自己的任务分支

### 已有本组未合并的任务分支

在仓库 **Code** 页，点击文件列表上方显示 `main` 的下拉框，输入完整分支名，点击已存在的那条。比如 G8 的第2章分支是 `chapter-02-a-g8`，末尾是 **字母 g + 数字 8**，不是数字98。

### 首次提交，或上一次 PR 已经 Merged

1. 先在分支框选择 `main`。
2. 再点分支框，输入新的任务分支名，例如 `chapter-01-a-g20`。已合并后的修订用 `chapter-01-a-g20-r2`。
3. 点击 **Create branch: … from main**。确认起点显示 `main`。
4. 回到文件列表，左上角现在应该显示自己的分支名。没有创建按钮时，先检查权限或按第8节 Fork。

章节号写两位；角色用 `a`、`b`、`c`；G编号与分工表一致。D/E用自己的整合任务名，例如 `chapter-01-d1-integration`。同一份未合并稿的补交继续用同一分支。

## 5. Add file 上传：先进入正确文件夹

1. 确认网页左上角仍是自己的任务分支。
2. 点击 **教材 → 对应章节 → 工作**。看网页路径，最后必须是这一章的 `工作`。
3. 点文件列表上方 **Add file → Upload files**。不要选 Create new file 来粘贴 Notebook 内容；`.ipynb` 应上传完整文件。
4. 点 **choose your files**，在电脑上找到第3节保存的文件，选中自己要交的正文、实验、报告等。也可以把这些文件直接拖到上传区域。
5. 等待上传完成，看清列表中的文件名。**在网页工作目录内上传文件本身，不要把整个“工作”文件夹再拖进去**，否则可能出现 `工作/工作/正文.md`。
6. 页面下方提交说明写清楚，例如“第01章 G20 A1：补全1.2推导和实验解释”。选择 **Commit directly to the … branch** 时，末尾必须是自己的任务分支，不能是 `main`。这里“directly”只表示保存到所选任务分支。
7. 点击 **Commit changes**；部分界面会弹出对话框，在对话框中再次确认分支和提交说明后提交。等页面回到文件列表，打开刚交的文件，核对内容确实是新版。

### 图片怎么交

正文写 `![说明](图片/A1-G20-误差曲线.png)` 时，图片应在这一章的 `工作/图片/`。先在网页点进 `图片`，再 Add file → Upload files，只上传对应图片文件；保存后返回 `工作` 上传正文。图片名大小写、空格必须与链接完全一致，不写 `C:\...` 之类本机路径。若 `图片` 文件夹尚不存在，可在 `工作` 的上传页面拖入本机的 `图片` 文件夹，并核对最终路径。

### 已有同名文件怎么更新

在**同一任务分支、同一文件夹**上传同名文件，GitHub会把它作为修改。上传前先看网页是否已有同组成员更新，避免用自己的旧副本覆盖新内容；由一位同学汇总后上传最稳妥。不要通过增加“(1)”来绕开文件名冲突。

## 6. 创建 PR：左边 main，右边自己的分支

上传完不代表已经进 main，还要申请合并。

1. 回到课程仓库，点 **Pull requests → New pull request**；若出现 **Compare & pull request** 也可以点。
2. 核对这两个框，按下面这个方向选：

```text
base: main              ← 接收作业的目标
compare: chapter-02-a-g8 ← 本组刚刚上传的来源（示例）

意思：把右边本组的修改，合到左边 main。
```

**不要选成 base: 本组分支、compare: main。** 方向反了是在把课程内容搬进本组分支，不是在交作业。Fork提交还需要核对仓库归属，见第8节。

3. 查看下方文件差异。应该是自己这一章的文件，没有整章模板被删除，也没有其他组文件被覆盖。
4. 点 **Create pull request**。标题如“第02章 G8 A1：正文初稿”；说明写本次完成哪些小节、哪些没完成、实验运行情况。不要只写“已完成”，也不要照交空模板。
5. 再点最终的 **Create pull request**。出现带 `#编号` 的页面就创建成功。复制这个页面的地址交给助教和需要复核的同学。

示例说明（按真实完成情况改）：

```text
第02章 / G8 / A1 / 初稿
正文：教材/第02章-逼近的智慧/工作/A1-G8-正文.md
本次完成：2.1—2.4讲解、推导及对应实验解释
实际运行：写系统、Notebook文件名、运行范围和输出情况
尚未完成：如实列出；全部完成则说明检查范围
附件：实验、习题、报告、AI记录的路径
```

## 7. 补交、修订和提供固定版本

PR仍为 **Open**：回到**原任务分支**重复第5节，原PR会自动包含新提交，不用重新建PR。PR已经 **Merged**：从最新main另建修订分支，再交新的PR。浏览器没有自动刷新时可刷新后再确认。

B/C需要固定版本时：打开PR的 **Commits** 标签，点最新提交的短编号，进入提交页面后复制完整SHA（地址末尾的40位编号，或页面复制按钮）。把 **PR链接 + SHA + 本次范围 + 依赖说明** 一起提供。网页提交不需要在本机执行 `git rev-parse HEAD`，本机可能还停在旧版本。详细复现方法见[06](06-B组如何在干净环境复现.md)。

## 8. 没有写权限：Fork 网页路线

1. 课程仓库右上角 **Fork → Create fork**，Owner选自己的账号。已有Fork直接打开，先在其main页通过 **Sync fork → Update branch** 获取课程更新；有冲突时先保留本组文件并联系助教。
2. 在**自己的Fork**内，按第4—5节从main建任务分支并上传。
3. 打开课程仓库的 **Pull requests → New pull request → compare across forks**。
4. 逐项选择：**base repository = prince19992516/-2026；base = main；head repository = 自己的Fork；compare = 自己的任务分支**。
5. 看差异，按第6节创建PR。只把文件传到个人Fork而没有向课程仓库创建PR，助教可能看不到提交。

## 9. 卡住时按现象处理

| 现象 | 原因与操作 |
| --- | --- |
| 没有 Add file 或无法保存 | 确认登录、仓库、分支和协作者邀请；无写权限走Fork；受保护分支不要强行上传，改用任务分支 |
| Upload files上传失败 | 网页单文件上限25 MiB，一次最多100个文件；不要拖环境或整个仓库。大Notebook先检查是否嵌入过多输出/图片，保留需要的证据，不要只改扩展名 |
| 文件传了，main没有 | 先看自己的分支；创建PR并等待Merged |
| PR显示没有差异 | 核对是否点了Commit changes、是否选对compare；已合并的旧任务需要新分支；没有实质修改的模板也可能无差异 |
| PR差异出现很多别组文件 | 常见是方向反了或用了旧分支；检查base=main、compare=自己的分支，别点合并 |
| PR已经建反了 | 在错误PR页面用Edit检查base；无法改成正确来源时，关闭这张错误PR，再按第6节重新创建。关闭PR不删除分支和文件 |
| 新建了错误分支但文件在里面 | 不要重新抄模板。保留这条分支，从该分支向main创建正确方向的PR，在说明中写正式组别 |
| 图片裂开 | 核对图片是否上传、是否在正文相对路径对应位置、文件名是否一致 |
| 出现工作/工作或正文(1) | 保留本机原件；将正确文件上传到第一层工作；核对后再在同一任务分支删除误传的本组副本 |
| 两人同时上传，提示冲突或新版丢失 | 停止覆盖，双方保留各自副本，请一人合并内容后再上传；不要删除另一人的内容 |

**完成标准：** 自己的PR可以打开，Files changed显示正确文件，尚未完成部分已说明；进入课程main则以PR显示Merged为准。

官方说明：[网页添加文件](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository)、[创建PR](https://docs.github.com/en/pull-requests/how-tos/create-pull-requests/creating-a-pull-request)。
