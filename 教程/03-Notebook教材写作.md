# 03 Notebook教材写作与验收

## 第一次写作先做这个小练习

按[环境教程](01-环境安装与运行.md)从课程助手打开JupyterLab。在左侧进入第一章并打开实验.ipynb；选中一个单元，工具栏“+”可以新增单元，类型下拉框选择Markdown或Code。Markdown写标题、正文与公式，Code写Python；Shift+Enter运行，Ctrl+S保存。

修改后先“Kernel → Restart Kernel and Run All Cells”，确认顺序执行成功，再保存。最后在[另一个终端窗口B](00-已经打开JupyterLab接下来怎么办.md)运行课程检查；终端命令不写进普通Code单元。关闭浏览器不会替你上传GitHub，上传需要按提交教程操作。

## 一个Notebook应当像一章教材

按“学习目标 → 问题定义和假设 → 数学推导 → 算法 → 实验 → 误差分析 → 练习 → 来源与局限”组织Markdown与代码。先解释代码为何存在，再给出实现，最后解释输出代表什么。

Notebook中的公式可使用 `$...$` 与 `$$...$$`。图片使用相对路径，如 `图片/convergence.png`。起步实验直接在代码中生成输入；需要真实外部文件时，在正文说明获取方法、来源和实际文件位置，不依赖预留的数据目录。自动执行以Notebook所在目录为工作目录，因此从本章目录出发编写路径。

## 可复现要求

- 从干净内核顺序执行；不依赖曾经运行但已删除的变量。
- 随机实验固定种子，如 `np.random.default_rng(2026)`，并记录多个种子的验证结果。
- 所需小数据提交并登记来源；较大数据提供生成/下载脚本、校验值和精简测试样本。
- 默认实验控制在CPU可运行的规模；单元超时180秒，训练扩展需与助教约定预算。
- 不使用交互输入、私有绝对路径或运行时临时安装依赖。
- 用解析解、独立算法、守恒量或高精度值建立预期；解释容差为何合理。

`np.testing.assert_allclose(actual, expected, rtol=..., atol=...)` 的绝对容差和相对容差需对应尺度。接近零的量尤其需要明确绝对误差判断。

## 三层检查

| 层次 | 检查什么 | 谁负责 |
| --- | --- | --- |
| 运行与结构 | 文件齐全、Notebook合法、代码能顺序执行、局部文件链接存在 | 脚本与CI |
| 数值证据 | 正常/边界/极端输入、单位、精度、收敛阶、参考解 | A自检、B验证 |
| 数学与独立性 | 假设、人工推导、反例、AI共同遗漏、真实工具使用 | C人工复核与助教 |

结构检查允许“待填写”模板存在；没有代码的B/C Notebook明确记为 `placeholder`，不会伪装成验证成功。AI陷阱脚本只查记录格式，不能自动发现所有陷阱。

## 故意错误如何写进教材

保留错误公式并用断言证明它失败，例如断言“错误算法误差大于某阈值”；若展示预期异常，用 `try/except` 捕获具体异常并断言确实触发。不要提交无处理的报错单元，或用跳过标签掩盖失败；检查器会执行被标记为跳过或允许报错的代码。

## 习题与来源

每章至少包括概念/推导、实现/数值验证、陷阱辨析三类题目，配套参考解答和验收标准。公开仓库中答案文件同样公开；学生版目录不展示答案只是阅读安排。

逐条记录引用的作者、标题、版本、页码或章节、链接及支撑的主张。AI生成的参考文献必须人工核对真实存在。不能只贴一段AI回复充当教材来源。
